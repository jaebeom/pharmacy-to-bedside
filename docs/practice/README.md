실행 전 계획, 정지 화면 확인, 실제 로봇 동작, 로그 재분석을 구분하며 실패와 미실행 상태를 유지한다.

## 공통 기록 규칙

- **실습 기록은 evidence 가 아니다.** protocol 을 정하고 재는 run 은 [`evidence/`](../../evidence/README.md)에 따로 둔다. 실습은 사람이 화면을 보고 문제를 찾는 자리다.
- 관측은 두 가지로 나눠 적는다. **사람이 본 것**(돌린 사람의 말, 취지 그대로)과 **로그로 본 것**(누가 어느 로그에서 확인했는지)이다.
- 문제에는 `P1`, `P2`… 번호를 붙인다. 고치는 PR 이 나오면 그 칸에 PR 번호를 적는다.
- 확인·측정 대상이 고친 그것인지 먼저 본다. 트리 sha, 기동 시각, 캐시 여부를 관측 첫 줄에 적는다([운영 규칙](../process/agent-workflow.md#확인-대상과-push-대상-918-에-더함)).
- 아직 받지 못한 값은 비우지 않고 "누구 보고 대기" 로 적는다. 추측으로 채우지 않는다.
- **"0건" 은 근거 줄을 붙일 수 있을 때만 쓴다**(9/20 규율). 전수를 센 명령과 그 결과가 있어야 한다. **셈이 없으면 "보고되지 않았다" 로 적는다.**
  - 셋은 섞어 쓰지 않는다: **"없다"**(관측했고 없었다) / **"보고되지 않았다"**(받지 못했다) / **"관측 범위 밖"**(그 자리에서 볼 수 없다).
  - **"전수" 라고 쓸 때는 무엇을 전수로 셌는지 적는다.**
    실습19 의 "웹 4xx 0건(`web.log` 전수)" 은 API 경로만 추린 것이었다(9/20).
- UR5 회차 로그를 읽는 법 넷(9/20 12g-12j 에서 굳음):
  1. **`ur5 placed` 는 시도 줄이다.** 성사는 `in_slot=` 과 `pouch=` 좌표로 본다.
  2. **접촉은 합계가 아니라 바퀴별·phase 별로 본다**(합계만 보고 한 번 틀렸다).
  3. **`ik_failed` 는 줄 수다.** 횟수는 `count=` 누적이다.
  4. **흡착이 진짜인지는 `distance` = `touch` dz + 0.005 로 가린다.**
  5. **`rtf` 는 `stop reason=` 줄에서만 읽는다.** 첫 `rtf=` 는 시작 줄의 `expected_rtf`(약 1.000)라 틀린다(9/20).
- **캡처·녹화 칸을 비운 채로 닫지 않는다**(9/20 재범 지시). 없으면 왜 없는지를 적는다. "없음" 한 줄로 넘기지 않는다. 먼저 원본을 요구한다.
- 중요 순간은 스크린 캡처로 남긴다(9/18 재범 지시, 실습7-a4 부터). 원본은 `master02` 로컬에 두고, 문서화할 때 대표 이미지 2-4장만 골라 `docs/images/practice/` 에 줄여 올린다(장당 200 KB 안팎 목표, 저장소 한도는 파일당 10 MiB). Isaac 캡처는 로봇이 보이는 것만 올린다(실습7-a4 는 기본 카메라가 벽 뒤라 37장 중 두 장만 올렸다). 웹 화면 캡처는 화면 상태나 UI 문제를 보여 줄 때 올린다(실습8 부터). 전송 때는 PIL 로 webp(q70 안팎)로 바꿔 base64 텍스트로 보낸다. 받은 뒤 sha256 을 대조한다.

## 로그 읽기 함정 (9/20 정리)

여러 실습에서 같은 자리에 걸렸다. 회차 하나짜리 사실이 아니라 **로그 형식에서 나오는 함정**이라 여기 둔다.

1. **`rtf` 는 `stop reason=` 줄에서만 읽는다.** 첫 `rtf=` 는 시작 줄의 `expected_rtf`(약 1.000)다.
2. **`DOCKED` 는 `stack.log` 에 없다.** 같은 순간의 줄은 `stub_fleet: dock_1 도착` 이다.
3. **`web.log` 에는 타임스탬프가 없다.** `POST` 의 벽시계는 sim stamp 를 `stack.log` 앵커로 환산해 잡는다.
   `/api/logs` 줄 수로 세려면 **주기를 먼저 실측한다.** 명목은 5 s, 9/20 실측은 **4.796 s/틱**이다(`refreshLogs` 가 타이머 외에도 불리는 것으로 보인다. 미검증).
   명목값으로 환산하면 98틱에서 **약 20 s** 빗나간다.
   총량 검산(1부 610틱 예상 대 615줄, 오차 0.8 %)은 **총량만 맞을 뿐 구간 오차를 못 잡는다.**
   - 규율: **고정 주기 타이머를 시계로 쓸 때는 참 시각을 아는 줄로 한 번 더 맞춘다.**
4. **`web.log` 의 "전수" 는 "API 경로" 가 아니다.** 정적 파일과 `favicon.ico` 404 가 섞여 있다.
5. **최신 run 을 `ls -t` 로 고르면 안 된다.** 리셋 직후 닫히는 이전 run 의 mtime 이 더 늦다.
6. **`refill.*fail` 류 패턴은 `resolved_args` 의 `"reset_fail"`·`"refill_loop"` 에 걸린다.** 이벤트 이름(`REFILL_FAILED`·`GOAL_REJECTED`)으로 좁힌다.
7. **1부의 `HOLD_RETURN` 은 정상이다**(`pharmacy_only=True`).
8. **`grep rokey_p3_` 는 Isaac 명령줄의 `--order-pool …/rokey_p3_orchestrator/…` 도 잡는다.** 노드 수는 `process started with pid`·`process has died` 로 센다.
9. **회차 종료 직후의 GPU 전체값으로 기준선을 판단하지 않는다.** 기준선은 `compute-apps` 가 비어 있는지로 본다.
   전체값은 창 상태에 따라 수백 MiB 출렁인다.
   9/20 에 종료 직후 574-583 MiB 였던 것이 약 7분 뒤 312 MiB 로 돌아왔다. 브라우저·파일 관리자 창은 그대로였다. **반환 원인은 가설이다.**

행위자에 대해서는 한 줄 더 있다: **"'자동이 아니다' 는 '그 사람이 했다' 가 아니다. 행위자는 시각·권한·정황으로 따로 가른다."**
