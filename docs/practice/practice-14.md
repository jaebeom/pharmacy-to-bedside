## 이 회차는 목적을 달성하지 못했다

**사람이 누른 배송 요청은 1부·2부 통틀어 0건이다.** `POST /api/requests` 가 1부 0 · 2부 0 이고, `POST /api/reset` 1건(16:10:27)은 대본대로 원격에서 넣은 시작 직전 리셋(안 A)이다. 팀원 리셋도 0건이다.

**시스템은 전 구간 정상이었다.** 아래 표와 같다. 즉 **이 회차가 못 답한 것은 시스템이 아니라 사람 경로다.**

## 확인되지 않은 일곱

이 회차가 답하려던 것들이다. **대본이 돌았으면 잡혔을 다섯**: confirm 창, 성공 토스트, `request_id` 모양, `destination_source`, 409 회복. **묶음까지 가야 잡히는 둘**: `bed_b1` 직접 입력, 주황 경고.

`destination_source` 는 **화면에서 볼 수 있는 조건이 따로 있다**(코드 확인, tree `45d7fe3`).

- `web/frontend/js/main.js:417` 의 `changed` 는 **서버가 목적지를 바꿨을 때만** 참이고, 그때에만 `:419` 의 `— 목적지는 … 로 적용됨 (…)` 이 붙는다.
- 바뀌지 않았으면 알림은 `요청 <id> 보냄 (1건|묶음 N건)` 뿐이고 `destination_source` 는 **응답 본문에만** 있다.
- 대본대로면(1인은 `bed_a1` 이 자동 입력되고 서버가 덮어써도 같은 값, 묶음 `bed_b1` 은 덮어쓰지 않음) **화면에는 안 나온다.**
- 확인 창 문구도 코드로 확정했다: 보내기 `main.js:404` `요청 <id> (1건|묶음 N건) 를 <destination_id> 로 보냅니다. 계속할까요?` / 리셋 `main.js:366` `시뮬을 리셋합니다. 진행 중 트립은 중단됩니다. 계속할까요?`

## 사람 쪽 자료

**글 2개와 화면 녹화 2개가 있다. 글은 녹화를 보고 쓴 3인칭 서술이고, 사람이 직접 조작한 관찰은 받지 못했다.** 그 이상(글의 세부 대조, 개인에 대한 평가)은 이 문서에 적지 않는다.

## 행위자를 적지 않은 것 둘

`16:04:17` 요청 대화창 GET 1회와 `16:07:39` 페이지 재로드가 있다(시각은 `/api/logs` 주기를 실측해 보정한 값. [실습 README 의 함정 3](README.md) 참고).

- 둘 다 착석 전이고 **원격 대본 동작은 아니다.**
- **로그와 프레임이 어긋난다**: 로그에는 대화창 전용 경로가 각 1건인데, 프레임(+150-205 s 1 fps 55장, +185-201 s 2 fps 32장)에는 대화창이 없다.
- **어긋남 그대로 남기고 행위자는 적지 않는다.**

신호 쪽도 같은 기준이다: **재범에게 가는 전달은 확인됐고, 재범 → 팀원 칸은 확인하지 못했다.**

## 기록 과정에서 난 잘못

- 관측 기록에서 셋: ① 시각을 재기 전에 "사람이 요청 창을 열었다" 고 적었다 ② "ROS 노드 감소 없음" 을 잣대로 썼다(틀린 잣대) ③ 16:02:06 경보는 오탐이었다.
- 원격 실행 쪽 하나: 16:16:00 의 5분 정적 경고를 바로 알리지 않았다.
- 원인 추정 하나: 빈 구간의 원인을 묻는 자리에서 **"신호가 중간 전달 칸에서 멈춘 것으로 보인다" 고 추정으로 말했다**. 근거는 "원격 실행 쪽이 중간 전달 칸에서 받은 메시지 0건" 하나였다. "세 건 모두 즉시 재범에게 전달했다" 는 사실로 바로잡혔다. #240 에는 그 추정이 올라가지 않았다.
- 옮겨 게시하면서 세 번(전부 먼저 알리고 되돌렸다): ① #379 댓글에 원문에 없던 배치 문장을 붙였다(16:23:16 게시 → 16:23:30 수정, 14초. 16:24:05 에 원문 문장으로 교체) ② 총평을 PR 별로 나눠 고쳐 쓰며 없던 문장을 보탰다(21:33:59 → 21:34:23, 24초) ③ 판정문에서 두 구절을 "독자에게 군말" 이라 판단해 **뺐다**(22:02:10 → 22:02:26, 16초). 규칙은 세 번에 걸쳐 **"옮겨 게시할 때는 보태지도 빼지도 않고, 나누지도 요약하지도 않는다"** 로 굳었다.
- 이 문서: 어림 시각을 그대로 쓸 뻔했다. **메시지 머리의 발신 시각은 근거로 쓰지 않는다** — `date` 로 찍었거나 파일명·로그 stamp 에서 나온 값만 쓴다.
