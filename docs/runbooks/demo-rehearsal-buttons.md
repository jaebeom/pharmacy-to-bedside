# 화면 버튼 리허설 (실습14) — 팀원용

> **상태: 지난 기록 (2026-09-23 기준).** 지금은 [병원 데모 런북](hospital-demo.md)을 따른다.

- 누구용: **웹 화면만 조작하는 사람.** ROS·터미널을 몰라도 이 문서만 보고 끝까지 갈 수 있게 썼다.
- 무엇을 하나: 9/21 시연 대본을 화면 버튼으로 한 번 돌려 본다. 발표 당일과 같은 순서다.
- 언제: 마스터를 혼자 쓰는 시간을 이슈 **#240** 에 예약하고 한다. 끝나고 결과도 #240 에 적는다.
- 무엇으로: 마스터 터미널에서 후보 버전 `45d7fe3`(v0.3.0 후보)으로 띄워 둔다. 팀원이 확인할 것은 아니다.
- 상태: **초안.** 시간 값은 실습14p·실습19 의 실측이다. **팀원이 실제로 막힌 곳은 실습14 미실행이라 아직 비어 있다.** 실습14 를 돌린 뒤 고친다.
- 대본의 근거와 코드 사실은 [9/21 시연 runbook](demo-0921-v2.md) 3절에 있다. 이 문서는 그 절차를 버튼 기준으로 풀어 쓴 것이다.

## 1. 시작 전에 (역할)

| 누가 | 무엇을 |
| --- | --- |
| 마스터 터미널(master01) | **호스트를 재부팅·로그아웃하지 않는다**(시연이 끝날 때까지 콘솔 세션 유지, 재범 결정). `tools/demo_v2.sh up` 으로 Isaac·팔·스택·웹을 띄운다. **녹화를 켠다.** 창을 좌우 반반으로 배치한다. 준비가 끝나면 "시작해도 된다"고 알린다 |
| 웹 화면(팀원) | `master01` 화면 앞에서 **웹 화면만** 조작한다. 터미널은 건드리지 않는다 |

- **신호는 두 사람이 직접 주고받는다.** 화면을 누르는 팀원이 "시작합니다"·"막혔습니다" 를 마스터 터미널 쪽에 바로 말하고, 마스터 터미널 쪽이 "시작해도 된다"·"2부 시작해도 된다" 를 바로 답한다. 사이에 다른 사람을 끼우지 않는다.

시작 전에 확인할 것:

1. **웹 주소**: `http://127.0.0.1:8000/?demo=1`(`demo_v2.sh` 가 여는 주소다. 호스트·포트를 바꿨다면 마스터 터미널 쪽이 알려 준다). **리허설도 발표와 같은 주소로 한다.**
   - `?demo=1` 은 글자가 큰 시연 화면이다. 이 문서의 확인 항목은 전부 여기서 보인다: 상단 띠(`연결`·`epoch`·`sim 시간`), `요청 넣기`·`리셋` 버튼, 트립 칸 전체, 주문 행(`order_id`·`상태`·`사유`), 조제기 칸과 `PAUSED`·`보충 중`·`STALE` 딱지, 보충 흐름 세 칸, 요청 창과 그 아래 문구.
   - **안 보이는 것:** 이벤트 타임라인, 에러 로그, 인터락 신호 칸, 단계 스텝퍼, 주문 표 머리글. 알람 칸은 알람이 있을 때만 나타난다.
   - 타임라인까지 보고 싶으면 주소에서 `?demo=1` 을 지운다(선택).
2. **창 배치**: Isaac 이 왼쪽, 웹이 오른쪽 반반이다.
   - 어긋나 있으면 마스터 터미널 쪽이 `tools/demo_window_layout.py` 를 한 번 돌린다. **브라우저 창이 화면에 보인 뒤에** 부른다.
   - `up` 직후 1 s 안에는 창을 못 찾는다. 그때 종료 코드는 3 이다.
   - 종료 코드가 0 이 아니면 손으로 옮긴다. 창을 누르고 `Super`+`←` / `Super`+`→`.
   - Isaac: 66,69 크기 927×1011. 웹: 993,69 크기 927×1011.
   - master01 에서 다섯 번 같았다(실습13e 세 번, 실습14p 두 번).
3. **화면 위쪽**이 "연결됨"(초록)이고 SIM 시간이 흐르는지 본다. 멈춰 있으면 시작하지 않고 마스터 터미널 쪽을 부른다.
4. **기동 직후에는 기다린다.** 팔이 계획을 푸는 데 약 60–65 s 걸린다(관측). 그동안은 아무것도 누르지 않는다.

- **기다리는 구간이 셋이다. 그 동안에는 아무것도 누르지 않는다. 화면이 멈춘 것이 아니다.**
  - 0번(자동 긴급 12–13 s): `현재 단계` 글자가 바뀌고 `sim 시간` 이 흐른다.
  - 4번(보충 22–35 s): 조제기 칸의 보충 줄에서 밝은 칸이 `정지` → `보충 중` 으로 넘어가고, 끝나면 줄이 없어진다. `sim 시간` 도 계속 흐른다.
  - 전환(약 100 s, 2부로 바꿀 때): 창이 내려갔다 다시 뜬다. **마스터 터미널 쪽이 "2부 시작해도 된다" 고 할 때까지 기다린다.**
- **왜 리셋부터 하나:** 기동 직후의 자동 긴급은 팀원이 앉기 전에 이미 지나간다. 리셋하면 새 회차에서 다시 나간다. **리셋 뒤 약 4 s 에 시작해 약 17 s 에 끝난다**(실습14p, 리셋 3회).
- **4번은 `PAUSED` 딱지를 기준으로 기다린다.** 사라지기 전에 누르면 같은 거부가 다시 난다.
- **기다리는 조건은 보충 횟수가 아니라 상태다:** 트립이 없고, `PAUSED` 가 없고, `보충 중` 이 아니면 다음으로 간다. **묶음 뒤에는 보충이 아예 안 뜰 수 있다**(9/21 `p14b`: 보충을 기다리다 5분 동안 아무것도 하지 않았다). 그 세 가지가 비어 있으면 기다리지 말고 넣는다.
  - 1인 배송을 보낸 뒤 `PAUSED` 가 사라지기까지 **22–35초**다. **리셋 직후 회차는 긴 쪽(약 35초)으로 잡는다.**
  - 갈리는 이유: 팔이 하나라 보충이 줄을 선다. 자동 긴급 직후에 1인을 넣으면 둘째 보충이 첫째가 끝나기를 기다린다(실습19: 대기 7.63 s + 수행 22.84 s). 첫째가 끝난 뒤에 넣으면 기다리지 않는다.
  - 자동 긴급만 돈 뒤라면(보충 한 건) 요청이 나간 때부터 약 25초다.
  - 보충 한 건은 약 20–23 s 다. 두 건이 겹치면 뒤의 것이 앞의 것을 기다린다.
- **기다릴 곳은 묶음 앞(4번)이다.** 1인(`ord-0001`, amox)과 자동 긴급(`ord-0002`, ibu)은 다른 약이라, ibu 보충 중에도 1인은 수락된다.
- **보충 중에는 리셋하지 않는다.** 그 보충이 버려진다.
- 트립이 도는 중에는 새 요청을 넣지 않는다. 눌러도 거부된다(4절).
- **기다림이 두 번 올 수 있다.** 트립이 끝나 버튼이 풀려도 보충이 남아 있으면 누른 뒤에 거부가 뜬다. 화면이 보충을 미리 판정하지 않기 때문이다. 그래서 5번은 조건을 둘 본다.
- 요청 창을 **취소**로 닫았다 다시 열어도 고른 주문·모드·목적지가 남아 있다. 보내기가 수락되면 비워진다. 그사이 쓰인 주문은 다시 열 때 선택에서 빠진다.
- 화면을 **새로고침해도 된다.** 트립·쓴 주문·리셋 상태는 서버에 있다. 고르던 주문과 입력한 목적지만 지워진다.

## 3. 정상인데 놀랄 수 있는 것

| 보이는 것 | 왜 정상인가 |
| --- | --- |
| 묶음 목적지가 `bed_b1` 인데 주황 경고 `후보 목록에 없는 목적지입니다 — …` | **그대로 보낸다.** 웹이 빈월드 zones 를 받아 후보 목록에 `bed_a1`·`station_a` 둘뿐이라 뜨는 안내다. 병원 zones(`zones.hospital.yaml`)로 띄우면 `bed_b1` 이 후보에 있어 안 뜬다 |
| 묶음에서 주황 안내 `고른 주문들의 침상이 갈립니다` | 고른 두 주문의 침상이 달라 첫 주문의 침상을 채웠다는 안내다. 대본은 `bed_b1` 이 맞다 |
| 리셋 직후 약 3.5 s 동안 버튼이 잠긴다 | 리셋이 끝나는 것을 기다리는 중이다(`barrier_running`). 곧 풀린다 |
| 내가 넣지도 않았는데 긴급 주문이 먼저 나간다 | 대본 0번이 그 자동 요청이다(재범 결정 25). 웹에서 긴급은 넣지 않는다 |
| 쓴 주문(`ord-0002` 등)의 체크박스가 잠겨 있다 | 같은 회차에서 이미 쓴 주문이다. 리셋하면 풀린다. 목록은 **대화창을 다시 열 때** 갱신된다 |
| 리셋·보내기에서 브라우저 확인 창이 뜬다 | 실수로 누르는 것을 막는다. 확인을 눌러야 나간다 |
| `?demo=1` 화면에 타임라인·신호 표가 없다 | 시연 모드가 숨긴다. 이 문서의 확인 항목은 모두 **트립 칸·주문 표·조제기 칸·상단 띠**로 볼 수 있다. 타임라인을 보고 싶으면 주소에서 `?demo=1` 을 지운다(선택) |
| 조제기 칸에 `STALE` 딱지 | 5 s 기다려 사라지면 그대로 진행한다. 조제기 소식이 3 s 넘게 안 왔다는 표시다 |
| `보충 중` 이 꺼졌는데 `PAUSED` 가 남고 보충 줄이 `정지` 로 돌아간다 | 보충은 끝났는데 조제기가 아직 재개를 알리지 않은 것이다. 실습13 에서 한 번 관측됐다(약 8 s). 실습13b 에서는 0건이다. 어느 쪽이든 **`PAUSED` 가 사라진 것을 기준으로** 한다 |
| 가끔 첫 트립만 5 s 늦다 | 팔이 아직 홈에 있다고 보고 출발을 한 번 거부한 뒤 다시 시도한다(실습13·13b 에서 1건씩). 그대로 기다린다 |
| 보충 중에 묶음을 보내면 빨간 문구 `<약품> 보충이 끝나면 다시 눌러 주세요` | 조제기가 그 약을 낼 수 없다는 뜻이다. `PAUSED` 가 사라진 뒤에 다시 누른다 |

## 4. 막혔을 때

| `…보충이 끝나면 다시 눌러 주세요` | `refill_in_progress` | 정상 | 조제기 칸의 `PAUSED` 가 사라진 뒤 다시 누른다(1인을 보낸 뒤 22–35 s) |
| `<요청번호> 가 끝나면 다시 눌러 주세요` | `trip_in_progress` | 정상 | 트립 칸이 `대기 중` 이 될 때까지 기다린다 |

| `… 이미 쓴 주문입니다. 목록을 다시 받았습니다` | `unknown_or_used_order` | 정상 | `사용됨` 딱지가 없는 주문을 고른다 |

| `2건에는 그 모드를 쓸 수 없습니다` | `bad_mode_for_orders` | **입력 실수** | **기다려도 안 풀린다.** 모드나 고른 수를 고친다 |

그 밖의 증상:

| 증상 | 볼 것 | 할 것 |
| --- | --- | --- |
| 화면 곳곳에 `STALE`, 위쪽이 `끊김` | 상단 띠의 `연결` 과 `sim 시간` | 셋이 같이 보이면 웹이 아니라 연결·스택 쪽이다. **마스터 터미널 쪽을 부른다** |
| 보충이 실패한다(조제기 칸이 오래 `PAUSED`) | 실패가 몇 번째인지 | **2회 연속 실패면 리셋한다**(재범 결정 34). 그래도 실패하면 부른다 |

**보충이 실패해도 화면은 알려 주지 않는다.**

> **화면은 보충 실패를 알려 주지 않습니다.** `PAUSED` 와 `보충 중` 이 그대로입니다. 복구는 리셋입니다.
> 포기를 알리는 이벤트가 없어서 웹이 실패를 구분하지 못하기 때문입니다. `REFILL_FAILED` 알람은 믿고 기다리지 마세요 — 마지막 보충 요청으로부터 120초가 지나야 뜨고, 그 사이 다른 약품 보충이 성공하면 아예 안 뜹니다.
> `보충 중` 이 1분 넘게 남으면 부릅니다.

- 실측(실습13e-A2): 포기 직후에도 화면은 `보충 중` 이었다. `REFILL_FAILED` 는 요청 뒤 약 127 sim s 에 떴다.
  - 그 알람의 글자는 `보충 실패 — 120 s 내 REFILL_DONE 없음` 이다.
- 스택 로그에서는 이렇게 보인다(실습13d). 세 번째 뒤에는 그 약품이 `PAUSED` 로 남고 복구는 리셋뿐이다.
  ```
  [WARN] [orchestrator]: Refill drug-ibu: 1/3 번째 실패(failed). 5 s 뒤 다시 보낸다.
  [WARN] [orchestrator]: Refill drug-ibu: 2/3 번째 실패(failed). 5 s 뒤 다시 보낸다.
  [WARN] [orchestrator]: Refill drug-ibu: 3/3 번째 실패(failed). 리셋 전까지 보충하지 않는다. 재고는 그대로다.
  ```
| 트립이 끝나지 않는다 | 트립 칸의 단계 이름 | 1분 넘게 한 단계면 부른다. 화면에서 되돌릴 방법은 없다 |
| 리셋이 안 풀린다 | 트립 칸 머리 | 35 s 가 지나면 빨간 `리셋 멈춤 — 사람 개입 필요` 딱지가 뜬다(시연 모드에서도 보인다). 그러면 멈추고 부른다 |
| 웹이 안 열린다 | 주소가 맞는지 | 마스터 터미널 쪽을 부른다. 웹만 다시 띄우면 된다 |

**중단 기준:** 아래 중 하나면 그 자리에서 멈추고 마스터 터미널 쪽을 부른다. 같은 조작을 반복하지 않는다.
- 같은 요청이 두 번 연속 거부된다(코드가 같을 때). 단 `refill_in_progress` 는 보충이 도는 동안 정상이다(30 s 남짓).
- 조제기 칸의 `PAUSED` 가 **1분** 넘게 남는다(정상 최대는 약 35 s 다).
- 보충이 2회 연속 실패하거나 한 번의 보충이 90 s 를 넘는다(코드 상한).
- 트립이 1분 넘게 한 단계에 머문다(코드 상한은 600 s 다).
- `RESET_STUCK` 알람이 뜨거나, 사유 없는 거부(`rejected`)가 난다.
- 화면 값이 멎거나 Isaac 창이 사라진다.

## 5. 기록

- **녹화는 마스터 터미널 쪽이 켠다.** 창 모드면 녹화가 기본이다([녹화와 캡처](demo-0921-v2.md#녹화와-캡처-재범-규칙-920)).
- 화면을 누르는 팀원은 단계마다 **"지금 캡처"** 라고 말하거나 아래 표에 시각을 적는다. 캡처는 일곱 장이다: 기동 직후, 자동 긴급 트립 카드, 1인 대화창, `PAUSED` 가 사라진 순간, 묶음 대화창(`bed_b1` 과 주황 경고), 묶음 `DOCKED`, 리셋 뒤 비워진 화면.

| 단계 | 시각(HH:MM:SS) | 화면에 보인 문구(있으면 그대로) | 이상 |
| --- | --- | --- | --- |
| 0 자동 긴급 `ord-0002` | | | ☐ 없음 ☐ 있음 |
| 3 1인 `ord-0001` 보내기 | | | ☐ 없음 ☐ 있음 |
| 4 `PAUSED` 사라짐 | | | ☐ 없음 ☐ 있음 |
| 7 묶음 `ord-0003`+`ord-0004` 보내기 | | | ☐ 없음 ☐ 있음 |
| 8 리셋 · 잠김 | | | ☐ 없음 ☐ 있음 |

"이상 있음"이면 그 화면을 찍고 문구를 글자 그대로 옮겨 적는다.

- 끝나면 마스터 터미널 쪽이 **파일 이름·크기·sha256** 을 실습 문서에 적는다. 녹화 파일은 저장소에 올리지 않는다.
- 결과는 **#240** 에 적는다: 어디까지 갔는지, 거부가 몇 번 났는지(코드별), 멈춘 곳이 있으면 그 화면과 시각.
- **못 한 것은 "없음" 으로 닫지 않는다.** 왜 못 했는지 한 줄 적고 대신 남긴 증거(로그·캡처)를 적는다.
