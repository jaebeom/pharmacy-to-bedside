# 작업 절차와 규약

**팀이 일하는 방식**을 둔다. 무엇을 만들지가 아니라 **어떤 순서로, 어떤 규칙으로 만드는지**다.
사람이 지켜야 하는 약속이므로 바꿀 때도 PR과 리뷰를 거친다.

## 무엇이 들어 있나

바뀌면 팀 전원의 작업 방식이 바뀐다. 개인이 임의로 예외를 두지 않는다.

| 문서 | 답하는 질문 |
| --- | --- |
| [Git 시작 가이드](git-start-guide.md) | 브랜치를 만들어 커밋·push하고 PR을 올리는 명령을 어떻게 치는가. 패키지 담당제, 브랜치 이름·수명, 워크트리 규칙 |

Git 가이드는 **도구 사용법**이라 여기 둔다. 위의 규약은 **우리 팀의 결정**이라 팀이 바뀌면 내용이 바뀐다.
Git 명령은 우리와 무관하게 참인 내용이 대부분이다. 그래도 제출 절차이므로 `process/`에 둔다.
파일 하나를 위해 디렉토리를 새로 만들지 않는다.

## 이 디렉토리를 고칠 때

- **충돌이 잦은 영역이다.** 규약이 바뀌면 여러 PR이 동시에 같은 파일을 건드린다.
  먼저 팀에 알리고 한 사람이 한 PR로 짧게 끝낸다.
  자세한 이유는 [Git 가이드의 병렬 작업 절](git-start-guide.md#병렬-작업에서-충돌-줄이기).
- **새 문서를 추가하면** 이 표와 [docs 색인](../README.md)에 같이 추가한다.
- **[CONTRIBUTING.md](../../CONTRIBUTING.md)와 [공통 규칙](repository-rules.md)이 상위 문서다.**
  여기 문서가 그쪽과 충돌하면 그쪽이 우선한다.
