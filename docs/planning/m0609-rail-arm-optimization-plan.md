## 1. 요구사항과 해결할 문제

사용자가 원하는 것은 **임무 수행 시 레일과 팔의 사용을 최적화하고 안정성을 높이는 것**이다.
구체적인 질문은 다음과 같다.

> 레일 이동으로 팔이 움직일 공간을 확보할 수 있다면, 팔을 오른쪽으로 조금 돌려 잡으면 되는데
> 왜 크게 접고 비틀어서 같은 작업을 수행하는가?

이 질문을 "팔 관절 속도를 올린다" 또는 "보기 좋은 홈 자세를 강제한다"로 축소하지 않는다.
빠른 외축으로 유리한 작업 위치와 회전 공간을 만들고, 팔은 필요한 접근·파지·인출·배치에 집중하도록
**전체 임무 경로**를 비교한다. 직관적인 경로가 충돌·자세·도달 제약을 만족하면 후보에 포함하고,
탈락하면 어느 단계의 어떤 제약 때문인지 설명할 수 있어야 한다.

"오른쪽 회전"은 사람이 이해하는 동작 의도이지 J1만 무조건 움직이라는 명령이 아니다.
J1 회전만으로 TCP 위치·방향이 바뀌고 팔꿈치·공구·파지물의 회전 영역도 달라진다.
필요한 보상 관절과 외축 이동을 포함한 유효 경로로 구현한다.

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| R1 | 외축 재배치 + 작은 팔 회전/접근 대안을 검토한다 | 같은 칸·시작 상태에서 기존안과 대안의 후보표 및 탈락 이유 |
| R2 | 불필요한 팔 접기·풀기·큰 회전을 줄인다 | 임무 전체 및 단계별 실제 관절 누적 이동량, 자세 전환 횟수 |
| R3 | 임무 완료시간을 줄인다 | 계획·정착·관측·복귀를 포함한 sim/wall 시간과 실패율의 쌍 비교 |
| R4 | 관절·TCP 움직임의 연속성과 추종 안정성을 높인다 | 명령/실측 위치·속도·가속도·jerk, 지연·점 생략·구간 경계 분석 |
| R5 | 파지·충돌·정지·리셋 보호를 약화하지 않는다 | 정상/실패 주입 시험, 링크·레일·파지물 전체 이동 경로 검증 |
| R6 | 선택 이유와 한계를 설명한다 | 선택/탈락 후보, 탐색 상한, 캐시 키, 예상/실측 시간 오차 기록 |

**최적화 순서:** 유효하고 검증 가능한 경로 확보 → 임무 시간 → 비슷한 시간에서 팔 움직임과 자세 변화 최소화.
안전 여유를 속도와 교환하는 단일 가중합으로 만들지 않는다. "레일 최대 사용"도 목표가 아니다.

**현재 가장 강한 구조적 가설:** legacy의 "짧은 도달 거리 우선 + 여유 최대 IK + 운반 전 홈 접기" 조합이
사용자가 기대하는 "외축 재배치 + 작은 팔 변화"를 비용으로 평가하지 못한다.
이는 영상 원인을 확정한 결론이 아니다. 활성 모드와 phase를 연결한 재현이 선행돼야 한다.

**A1(기존 후보의 점수만 변경)과 C1(외축 재배치 + 작은 팔 방향 전환)은 다르다.**
현재 잡기 후보는 `back=0.40-0.50 m`, `side=±0.15 m`, `dz=0.30-0.35 m`로 좁혀져 있다.
E1 주석은 과거 격자에서 짧은 도달의 첫 통과 자세를 남겨 기동 계산량을 줄였다고 설명한다.
E3도 같은 후보를 바탕으로 보정한다. **C1의 충분한 생성·검증은 A2의 후보 확대에서 수행한다.**
A1에서 차이가 없어도 C1의 반증이나 물리적 불가능 판정이 아니다.
고정 TCP yaw와 팔 J1 회전량은 서로 다르므로, 기존 후보 중 작은 관절 변화가 우연히 나올 가능성까지 부정하지 않는다.

여전히 가설**이다. 다른 회차의 시간 범위나 성공 횟수를 이 표본의 안전·효율 증거로 합치지 않는다.

## 3. G0: 실행 식별과 반증 가능한 진단

2.4절로 실행 태그·모드·칸·seed·계획값은 보고 수준에서 확보했다. G0는 완료로 닫지 않고 아래 누락 자료를 보강한다.
이미 받은 값을 다시 "전부 미확인"으로 돌리거나, 원본 확인 없이 전체 진단 완료로 승격하지 않는다.

1. 현장 Git SHA, dirty diff 해시, 설치 패키지 경로와 빌드/기동 시각, 명령 전체와 parameter dump.
2. `scene_version`, `rail_enabled`, `v2_guarded_module_path`, `use_sim_time`, `open_loop`, selfdemo 여부.
   `tools/demo_v2.sh`와 `P3_V2_GUARDED_MODULE_PATH`의 실제 환경값·생성 명령을 보관한다.
   시연 기본 false는 노드 기본값보다 우선한다. 원통은 true에서도 legacy, 모듈만 guarded 비교 대상이다.
3. inventory 원문/해시, USD·URDF·TCP·collision 설정 해시, 레일 한계와 실제 drive 값, 제어/physics/render 주기.
4. epoch·goal ID·cell ID·item kind·slot·seed·초기 팔/레일 관절값·초기 파지 상태·캐시 hit/miss.
5. 영상 재현의 선택 후보, phase 경계, 명령·실측·물체 상태를 같은 sim timestamp에 연결한 기록.

## 4. 목표 설계: 임무 단위 후보 비교

### 4.1 후보가 반드시 포함할 것

후보 하나는 `(픽 레일 위치, 접근 팔 자세, 인출 경로, 운반 자세, 외축 운반 경로, 배치 레일 위치,
배치·해제·후퇴 경로, 복귀 경로)`의 조합이다. 픽 지점의 팔 길이만 최적화하지 않는다.

| 후보군 | 검토 목적 |
| --- | --- |
| C0 기존 경로 | 기준선 재현. 개선 후보보다 제약이 약하면 "안전 동등" 비교에서 제외하고 차이를 보고 |
| C1 레일 옆/앞뒤/높이 재배치 + 작은 팔 방향 전환 | 사용자 예시의 직접 검증. 방향 전환이 가능한 공간을 먼저 확보 |
| C2 완전 인출 자세 또는 소수의 검증된 운반 자세 유지 + 외축 이송 | 부하를 쥔 채 홈으로 접었다 다시 펴는 왕복 제거 |
| C3 전방 통로 우회 + 검사된 회전 위치 | 직행이 팔/기둥/선반/파지물 충돌로 불가능할 때의 대안 |

초기 A1은 기존 유한 레일 후보와 시드를 재사용해 선택 기준만 비교한다. **A1 성과가 작아도 A2의 C1 검증을 생략하지 않는다.**
A2는 과거 격자를 참고하되 side=0과 더 넓은 옆/앞뒤/높이 오프셋, 허용 팔 자세를 포함하는 bounded 탐색을 설계한다.
리뷰의 side 최대 ±0.6 m는 탐색 예시일 뿐 승인된 설정값이 아니다. 실제 레일 한계·환경·도달·운반 경로로 범위를 정한다.
잡기 TCP yaw를 임의로 자유롭게 하지 않는다. 슬롯 접근축을 유지한 레일 재배치와 관절 시드 탐색부터 하고,
물체/파지 대칭성이 허용하는 추가 방향만 별도 검사한다. 각 후보의 생성 여부와 budget 종료 이유까지 기록한다.
guarded 활성화 자체도 이 확대를 대신하지 않는다. E3가 기존 후보에서 보정하는 범위를 함께 기록한다.
C1 후보는 현재 상태와 앞 단계 해를 우선 시드로 쓰되, 실제 관절 한계 안의 동치 각도와 추가 시드도 검사한다.
±2π를 무조건 최단각으로 접어 버리면 한계·배선·경로가 달라질 수 있으므로 실제 실행 각도로 검증한다.
J4/J6 고정, 모든 작업의 roll 고정, 전역 홈 강제로 "자연스러움"을 대신하지 않는다.

현재 C1 생성 범위에 유효한 "옆으로 이동 후 회전"이 없으면, 후보 생성 실패와 물리적 불가능을 구분한다.
탐색 budget 소진도 "해가 없다"가 아닌 `search_budget_exhausted` 등 내부 진단으로 남긴다.

### 4.2 선택 규칙

1. **hard gate — 구현 목표이며 현행 보장 목록이 아니다.** 신선한 시작 상태부터 확인한다.
   관절/레일 한계와 여유, 파지 방향, 완전 인출, 손목/자코비안 조건을 검사한다.
   링크·그리퍼·파지물·승강판·기둥·환경·필요 자기 충돌 쌍은 경유점뿐 아니라 전체 경로에서 검사한다.
2. 통과 후보는 실행할 시간 프로파일로 retime하고, retime이 새로 만든 연결 구간도 다시 검사한다.
3. `T_est = 계획 대기 + 이동 + 필수 정착 + 파지/해제 관측 대기 + 계약상 복귀`로 비교한다.
   cache hit/miss 비용은 따로 산정하고 중복 합산하지 않는다. 센서 대기 실측이 없으면 범위/미추정으로 표시한다.
4. 최소 시간 후보와 사전 설정한 시간 동등 범위 안에 있는 후보 중 팔 누적 이동·큰 자세 전환이 작은 안을 선택한다.
   동등 범위는 pilot에서 정하고 acceptance 전에 고정한다. 더 큰 충돌 여유는 후순위 동률 기준이다.
5. 같은 입력에서 같은 결과를 내도록 마지막 동률은 고정 candidate ID로 해소한다.

팔 비용은 `sum_j sum_k abs(q[j,k+1]-q[j,k]) / range[j]`처럼 무차원 정규화를 사용하고,
원시 관절별 rad도 함께 남긴다. 외축 m와 관절 rad를 그대로 더하지 않는다.
같은 유효 후보군에서 **시간도 더 길고 팔 움직임도 더 큰 지배당한 후보**가 선택되면 이유가 있어야 한다.
필수 여유를 만족한 이후의 여유 점수만으로 그 선택을 정당화하지 않는다.

목표는 **정해진 유효 후보 집합 안의 최선**이다. 전역 최적해라고 부르지 않는다.
근소한 시간 개선을 위해 탐색 지연이 더 커지는지, 실측 시간 오차가 후보 순위를 뒤집는지도 평가한다.

### 4.3 경로 단계와 동시 동작 범위

기본 후보는 다음 순서다. 목적지는 M0609의 **조제기 수납부**이며 UR5가 약포지를 집는 컨베이어와 구분한다.

1. 현재 상태를 확인하고 외축으로 접근·회전 공간을 확보한다.
2. 팔 자세를 작게 조정한 뒤 방향을 유지하며 진입한다.
3. 파지를 확인하고 필요한 만큼 들어 올린다.
4. 물체·그리퍼 형상을 기준으로 선반에서 완전히 인출한다.
5. 검사된 운반 자세를 유지하며 외축으로 조제기 수납부까지 이송한다.
6. 배치 자세를 정렬하고 삽입·해제를 확인한다.
7. 방향을 유지하며 후퇴한 뒤 검사된 빈손 복귀를 수행한다.

- 진입/인출 축은 inventory의 접근 방향과 검증된 TCP 변환으로 정한다. 접근축이 다르면 거부 또는 명시 지원한다.
- 원통은 대상·파지의 대칭성이 허용하는 yaw만 후보화한다. 모듈은 삽입축·단면·파지물 방향 제약을 유지한다.
- 인출 거리는 물체의 뒷면, 손가락, 선반 앞면, 측정 오차와 여유로 계산한다. TCP만 밖이라고 완료하지 않는다.
- 레일은 팔을 그대로 유지해도 **팔 전체와 물체가 월드에서 이동한다**. 고정 팔 자세 하나의 충돌 검사로 끝내지 않는다.
- 초기 구현은 팔/레일 교대 실행을 유지하면서 불필요한 접힘과 잘못된 위치 선택을 줄인다.
  기존 `safe_phases`에 임의 자세를 추가해 인터록을 우회하지 않고, 검사된 운반 경로와 신선한 실측 자세를 허가 근거로 삼는다.
- 레일 z와 xy 동시 이동, 외축과 팔의 동시 동작은 후속 단계다. 동기 시간축의 전체 이동 영역,
  합성 TCP 속도, 양쪽 추종 오차와 하나가 멈췄을 때의 정지 동작을 검증해야 한다.
  기존 "고정 축 정지" executor를 그대로 둔 채 동시 명령을 넣지 않는다.

### 4.4 부드러움과 안정성

경로 선택 개선과 시간 프로파일 개선을 분리해 A/B 검증한다.

- 진입/파지/해제/다른 제어 주체로 넘기는 경계의 필요한 정지를 보존한다.
- 열린 공간의 연결은 속도·가속 연속성, jerk 제한을 갖는 시간화/블렌딩을 검토하되 새 경로를 다시 충돌 검사한다.
- quintic 진행률만으로 관절 polyline의 꺾임이나 실제 drive 응답까지 부드러워졌다고 판단하지 않는다.
- legacy `_stream` 지연 시 점 생략 정책을 계측하고, 검증된 점을 보존하는 bounded slowdown/중단 정책으로 개선한다.
  점을 몰아서 보내거나 timeout을 임의 연장해 만회하지 않는다.
- 같은 경로에서 명령은 매끄럽고 실측만 진동하면 drive·접촉·파지 모델·지연을 별도 수정한다.
  stiffness를 무조건 올리거나 모든 속도를 낮추는 것을 경로 최적화 성과로 보고하지 않는다.
- 자기 충돌, 인접 재고, 동적 물체 등 현재 bbox 검증의 누락 범위를 명시하고 지원 범위를 한정한다.
  특히 E1의 `min_reach=0.40 m`는 자기 충돌 모델 부재를 보완하려는 휴리스틱이며 자기 충돌 검사와 동등하지 않다.
  샘플 충돌 검사에는 구간 세분화와 오차 여유를 적용하며 연속 충돌 인증으로 표현하지 않는다.

## 5. 실패 동작과 계약 경계

안정성 증대는 정상 동작의 외형뿐 아니라 중단·관측 소실·리셋 시 올바르게 멈추는 것을 포함한다.

| 상황 | 계획하는 동작 |
| --- | --- |
| 계획 없음, 미지원 형상, budget/시한 부족 | 실행 전이면 명령 없이 거부. 미검증 legacy 경로로 자동 fallback 금지 |
| 시작 실측이 계획 시작과 다름 | 실행하지 않고 정지 상태에서 재계획 또는 거부 |
| 고정 축 drift, joint/holding stale, 경로 이탈 | 신선한 상태 기반 hold 요청과 fault 기록; 자동 홈/그리퍼 열기 금지 |
| 파지/해제 관측 불일치 | 타이머 만료를 성공으로 바꾸지 않음. 물체 상태 불명은 별도 실패로 기록 |
| 취소·리셋·시간 역행 | epoch/reset fence 준수. 옛 계획의 늦은 명령·완료 이벤트 차단 |
| 캐시 입력 변경 | scene·cell·TCP/형상·한계·속도/가속/jerk·planner 버전·초기 상태 가정의 키를 갱신/무효화 |
| 피드백 단절로 hold 불가능 | 정지 요청과 정지 관측을 구분. 제어기 로컬 watchdog/만료 명령 정책을 별도 확인 |

E4의 guarded 모듈 보호를 원통 지원에 재사용할 수 있는지 검토한다. Bool holding은 명령 ACK가 아니며,
센서 수신만으로 물리적 파지력을 인증하지 않는다. 파지 부착/teleport가 진동·미끄러짐을 가리는지도 L3에 기록한다.

첫 구현은 기존 `Refill`, `REFILL_DONE.detail`, reset과 결과 소비자를 유지한다. 진단 추가는 우선 로그/sidecar로 한다.
원통까지 보호를 확대하면 실패 후 자동 복귀 등 행동 의미가 바뀔 수 있으므로 orchestrator와 함께 검증한다.

**계약 대조 항목:** 현재 배송 계약 2.3의 M0609 설명은 결과 뒤 홈 복귀라고 적혀 있으나,
E5와 패키지 README에는 결과 전 복귀 및 guarded 완료 확인이 있다.
이 계획은 어느 한쪽을 조용히 덮어쓰지 않는다. G0에서 활성 모드별 이벤트 순서를 확인하고,
구현 PR에서 계약·소비자·시험을 함께 정리한다. 성능 측정은 `REFILL_DONE`만으로 끝내지 않고
실측 빈손·홈/다음 임무 가능 상태까지 포함해, 복귀 비용을 숨기지 않는다.

## 6. 관측과 지표

모든 기록에 `run_id, epoch, goal_id, cell_id, kind, planner_mode, candidate_id, phase, sim_stamp`를 둔다.
호스트별 wall monotonic은 직접 서로 빼지 않는다. 원본·수집기 버전·설정 해시를 함께 보관한다.

| 분류 | 필수 기록/정의 |
| --- | --- |
| 시간 | goal 수락→장착 관측, goal 수락→복귀/준비 관측, 계획 wall 시간, 단계 이동·정착·그리퍼 대기, RTF |
| 움직임 | 명령 및 실측 6축 q/dq, 외축 3축 위치/속도, 관절별 누적 rad, 외축별 누적 m, TCP 위치/방향 |
| 연속성 | phase 양쪽의 위치/속도/가속 차, 큰 관절 변화, 명령 seq 누락·발행 간격·추종 오차 |
| 부드러움 | 축별 peak/RMS 가속·jerk, 예상 밖 중간 정지 수/시간. 미분·필터·최소 dt는 protocol에 고정 |
| 안전·성공 | 파지/해제/안착 관측, 낙하, 접촉/관통, 한계·특이점·drift·stale·timeout·취소 및 실패 원인 |
| 후보 선택 | 레일 목표·팔 경로·운반 자세·예상 시간 분해·팔 비용·최소 여유·유효/탈락/미평가 수·탈락 phase/쌍 |
| 비교 | 기존안과 C1-C3의 차이, 예상/실측 시간 오차, 동일 조건 양쪽 성공 쌍의 시간비와 전체 시도의 성공률 |

위 비교 행의 시간비는 성공한 쌍에서만 산정하고, 전체 시작 횟수·한쪽 실패·양쪽 실패·누락 수를 나란히 표시한다.
실패한 시행을 지워서 개선율을 높이지 않는다. timeout은 실제 중단 시간·실패로 기록한다.
실측 미분에는 timestamp 역행·중복·작은 dt 처리와 필터 지연을 명시한다. 로그가 부족하면 "부드러움 검증 미완료"다.

## 7. 검증 설계와 제안 합격 기준

수치 목표는 **사용자가 이미 승인한 합격선이나 달성 결과가 아니라, 리뷰할 초기 제안**이다.
[측정 정책](../policy/metrics.md)에 따라 pilot protocol과 acceptance protocol을 별도로 검토·고정한다.
기존 frozen protocol 및 run은 수정하지 않는다. 자산/기구학 대조가 끝나기 전 물리적 안정성을 통과로 표시하지 않는다.

### 7.1 단계별 시험

| 계층 | 시험 | 기대 증거 |
| --- | --- | --- |
| L1 | first-feasible보다 빠른 뒤 후보, 최소거리와 최소시간 불일치, 충분한 여유의 작은 회전안, 안전 미달의 빠른 안 | 후보 선택 및 탈락 이유; 유효 후보 내 지배당한 해를 선택하지 않음 |
| L1 | 시작/끝은 안전하나 중간 충돌, 파지물 긴 경우, 기둥/자기 충돌, IK 가지·±2π, LIN 이탈 | 거부 또는 제한된 재계획; 한계/여유 완화 없음 |
| L1 | retime/blend 새 연결선, 낮은 주기·지연 tick, 캐시 조건 변경, 후보 budget 종료 | 실제 전송 경로 재검사, 점 생략/몰아보내기 없음, 명시적 무효화/거부 |
| L2 | 원통/모듈·guarded/legacy 분기, 시작 상태 불일치, stale/역순/리셋 중 계획 완료 | 옛 명령/성공 0건, 실패 시 자동 홈·해제 금지, 단일 종결 |
| L2 | 고정 축 drift, holding 소실, 해제 실패, 시계 정지, 취소·deadline | 보호 유지, fault와 실제 정지 관측의 구분 |
| L3 | 같은 슬롯·물체·초기 상태·seed의 기존/후보 재현 | 동기 영상+로그, 실제 링크/TCP 대조, 단계별 시간과 팔 이동량 |
| L3 | 화면 녹화 on/off, 정상/지연 자원 조건, 인접 재고·한계 근처 | RTF·명령 간격·실측 진동 분리, 지원 환경별 결과 |

테스트 위치는 기존 `test_scene_v2.py`, `test_module_path.py`, `test_module_execution.py`,
`test_module_node.py`, `test_m0609_rail.py`, `test_m0609_refill_finish.py` 등을 재사용한다.
단순히 새 점수 함수를 그대로 복제한 시험 대신, 위 반례와 executor가 실제 보내는 경로를 검사한다.

### 7.2 A/B와 회귀 매트릭스

- **시연 뒤 첫 제한 L3 후보는 기존 모듈 구현의 B0/B1 비교**다. 로그로 식별한 `upper_left/r1c0`의
  동일 초기 상태에서 legacy false와 guarded true를 비교한다. seed=7만 같게 두면 다른 칸이 뽑힐 수 있으므로
  재고·draw와 선택 cell을 확인하고 다르면 쌍 비교에서 분리한다. 실행 전에 오프라인 feasibility·시한·중단 조건을 확인한다.
  초기 1쌍은 탐색 관찰이며 합격 판정이 아니다. 이후 고정 protocol의 반복으로 확대한다.
  이 B0/B1은 여러 경로/보호가 함께 다른 기존 구현 비교이므로 H2만의 인과효과나 A2 완료로 보고하지 않는다.
  원통에는 이 플래그 비교로 guarded 경로가 생기지 않는다.
- 고정 manifest에 정상 지원 전체 칸 목록을 기록한다. 원통/모듈, 상/중/하단, 좌/우 끝, 가까운/먼 수납,
  초기 팔 방향, 빈손/부하 운반과 복귀를 구분한다. 칸 수를 영상만 보고 고정하지 않는다.
- 사용자 예시를 대표 반례로 만든다: **옆 레일 공간이 있고 작은 방향 전환으로 접근 가능한 장면**,
  그리고 **겉보기 공간은 있으나 팔꿈치/파지물이 충돌하는 장면**을 짝으로 둔다.
- 전체 칸의 오프라인 feasibility를 확인한 뒤, pilot 대표 조건은 정책별 최소 5회 쌍 비교를 제안한다.
  acceptance는 고정된 대표 조건별 20회 쌍 비교를 초기 제안으로 하되 pilot 분산과 자원으로 사전에 확정한다.
  적은 반복을 높은 안전 신뢰도의 증명으로 해석하지 않는다.
- 실험 순서는 같은 초기 상태 복원 후 AB/BA로 교차한다. seed·재고·scene·drive·속도 상한·캐시 조건을 맞춘다.
- A0 기존 선택, A1 후보 집합 동일/점수만 변경, A2 운반 자세·후보 확대, A3 시간 프로파일 개선을 분리한다.
  A2도 후보 생성 범위와 운반 자세 정책을 각각 고정한 하위 비교를 두어 효과를 분리한다.
  A1 무개선은 H1a에 대한 결과일 뿐, H1b/C1의 반증이 아니다. A2 오프라인 후보표를 C1 검증의 필수 산출물로 둔다.
  외축/팔 동시 동작은 이 결과 이후 별도 A4로 다룬다.
- cold cache와 warm cache를 각각 보고하며 실패·거부·개입·계획 지연도 분모와 기록에 남긴다.

### 7.3 합격 문턱 제안

| 항목 | 초기 제안 및 판정 방식 |
| --- | --- |
| 보호 | 시험 집합에서 금지 충돌·한계 초과·낙하·잘못된 성공·리셋 뒤 옛 명령 0건. 발생 시 속도 성과와 무관하게 실패 |
| 성공/지원 범위 | 이전에 지원한 필수 칸이 새로 미지원이면 원인·대안 필요. 전체 시작 분모의 성공률 악화 없음; 미해결 실패가 있으면 완료 아님 |
| 효율 | 병목 재현 조건의 paired 임무시간 중앙값 20% 이상 감소를 제안. p95는 악화 없음. 셀/종류별 수치도 보고 |
| 팔 이동 | 같은 병목 조건의 정규화 팔 누적 이동 중앙값 25% 이상 감소를 제안. 안전상 필수 접힘은 제거 대상 아님 |
| 부드러움 | 전송 위치 점프 0건, 검증된 점 생략 0건, 축별 v/a/jerk 승인 상한 이내. 실측 추종 오차·진동 p95 악화 없음 |
| 설명 가능성 | 선택/탈락 후보와 비용 분해 100% 기록. C1이 없거나 탈락한 이유와 탐색 제한을 재현 가능 |

20%·25%는 측정 전 가설적 목표이며 보장치가 아니다. 기준선이 이미 효율적이면 목표 적용 조건을 pilot에서 수정하고
새 acceptance를 고정한다. 결과를 본 뒤 기준을 바꾸어 같은 run을 합격시키지 않는다.
2.4절의 한 표본에서도 부하 홈 전환은 2.25 s다. 따라서 20%를 "홈 접기만 없애면 달성"하는 약속으로 해석하지 않는다.
정착·추종·jerk·특이점·최소 여유의 물리 상한은 현장 모델·drive·측정 해상도로 정해야 한다.
**필수 상한 미결정 상태에서는 acceptance 실행과 완료 판정을 시작하지 않는다.**

담당은 기존 역할 기준의 **제안**이며 사람에게 배정·수락됐다는 뜻이 아니다.

| --- | --- | --- | --- |
| G0 / P0 | 실행 식별·진단 / observer + manipulation | 2.4절 보고의 원본·설치본 대조, 누락 관절/명령 계측 | 보고된 식별 재사용, phase 정렬, 기준선·계약 순서 확인 |
| G1 / P0 | 후보·비용 계측 / manipulation | `scene_v2`, `pick_plan`, `module_path`, 캐시·진단 | 동작 변경 없는 기존 후보표, A1 평가와 A2 생성 범위 명세. C1 가능 판정은 G2 |
| G2 / P0 | 원통/모듈 공통 임무 비용과 운반 대안 / manipulation + simulation | 위 계획기, payload 형상, 경로 검증; 필요한 만큼만 공통화 | 동일 제약의 후보 비교, 홈 접기 대체, 원통 완전 인출/LIN 및 운반 검사 |
| G3 / P0 | 실행 보호·연속성 / manipulation | `m0609_arm_node`, `module_execution`, `refill_sequence` | 원통 보호 동등성, 점 보존, 재시간화, 실패/취소/리셋 L1/L2 |
| G4 / P0 | 독립 교차검증·현장 A/B / reviewer + observer | 신규 protocol·evidence·runbook | 기준 SHA 고정 L3, 실패 포함 결과, 영상·로그 동일 판정 |
| G5 / 후속 | 검증된 공간에서 동시 동작 / manipulation + simulation | 동기 궤적/양축 executor·정지 경계 | 별도 계약·실험, 순차 최적안보다 실제 이득이 있을 때만 채택 |

G2와 G3는 함께 통합 검증하되 원인 분리를 위한 작은 PR로 나눈다. G0 전에 기본 설정을 바꾸지 않는다.
**P0는 과제 우선순위이며 9/21 시연 스택 교체 지시가 아니다.**
시연 보호는 [실습13 운영 결정](../practice/practice-13.md)과 F1의 운영 보고를 따른다.
시연 전에는 문서·원본 읽기·별도 개발 환경의 정적/오프라인 검토로 제한하고,
이 과제의 runtime·기본값·`demo_v2.sh` 변경 및 guarded L3 비교는 **9/21 시연 뒤 별도 슬롯·PR**에서 진행한다.
시연 핫픽스 레인과 최적화 레인을 섞지 않는다. 이 문서 병합은 현장 보호 해제나 실행 승인이 아니다.
G4를 통과하기 전 사용자 문제를 해결 완료로 닫지 않는다. 계획 PR 병합은 구현 완료가 아니다.
현재 문서 PR은 다른 레인의 코드를 수정하거나 마스터 실행 슬롯을 예약하지 않는다.
현장 실행은 기존 슬롯 이슈 #240에서 별도 조율한다.

## 9. 배포·중단·롤백

- 기존 정상 커밋과 scene/config/model/protocol 해시를 baseline으로 보존한다.
- 변경은 명시적 planner mode로 제한 도입하고 선택 모드를 로그에 남긴다. 기존 보호를 전역 비활성화하지 않는다.
- 계획 후보 실패 시 자동으로 미검증 경로를 실행하지 않는다. 실행 전 거부와 실행 중 hold를 구분한다.
- 첫 forbidden contact·낙하·관측 위반·구버전 명령·예상 밖 추종 이탈이면 해당 후보 실행을 중단하고 run을 보존한다.
- 물체를 쥔 채 planner를 즉시 바꾸거나 홈으로 보내지 않는다. 관측된 정지/물체 상태를 확인한 운영 절차 후
  baseline 커밋·설정으로 되돌리고 새 run을 만든다. 옛 캐시를 재사용하지 않는다.
- README·계약·실행 플래그·소비자 이벤트 의미를 함께 검토하고, 변경 버전으로 배포됐는지 확인한 뒤 측정한다.

## 11. 현재 문서 작성 단계의 검증 범위

- 수행: 사용자 영상 프레임 확인, 기준 SHA의 계획기·실행기·기구학·계약·선행 PR 정적 대조,
  PR 피드백·슬롯/결과 보고 읽기, `v0.3.0` 대 기준 SHA의 E1-E8 diff, 시연 스크립트/시험 대조.
- 미실행: 사용자 영상의 현장 재현, Isaac/ROS 실행, 실제 후보 A/B, 개선율 측정, 물리적 안정성 검증.
- 문서·링크·저장소 검사는 PR 본문에 명령과 실제 결과를 기록한다.
- 개선율, 원인 확정, 구현/현장 검증 완료를 주장하지 않는다.
- 검토 결론을 "자세 평가 로직 수정만으로 해결", "guarded를 켜면 깊은 접힘 해결", "경고 0이면 점 생략 없음"으로
  확대하지 않는다. 후보 생성·실행 보호·형상 대조가 별도로 필요하고 로그의 관측 범위를 넘는 결론이다.
