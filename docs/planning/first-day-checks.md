# 첫날에 먼저 확인할 것

> **언제**: 2026-09-15 (화) — [일정](schedule.md)에서 **D1** 이라고 부르는 날이다.
> 일정 문서는 날짜를 `D1`-`D10` 으로 세는데, `D1` 이 프로젝트 첫 작업일이다.
> 9/14(월)은 저장소·네트워크 셋업으로 썼다.

## 이 문서는 무엇인가

[기획서](p3-project-plan.md)에 적힌 시나리오가 **애초에 가능한지** 먼저 눌러보는 것이다.
아래 네 가지 중 하나라도 안 되면 시나리오를 다시 써야 한다.
그래서 시나리오를 더 자세히 쓰는 것보다 이게 먼저다.

이런 걸 [스파이크](../README.md#용어)라고 부른다. 본 작업에 들어가기 전에
"되는지 안 되는지"만 빠르게 찔러보는 짧은 실험이다.

**예쁘게 만들지 않는다.** 목표는 "동작하는 기능" 이 아니라 **"되는지 안 되는지 아는 것"** 이다.
확인이 끝나면 그 코드는 버려도 된다. 다만 **무엇을 어떻게 돌렸고 결과가 어땠는지**는 이슈에 적는다.
오늘 결과는 pilot(탐색용)이며 최종 평가 수치에 넣지 않는다.

## 어떻게 쓰나

1. 아래 항목을 담당자별로 나눠 오전에 각자 확인한다. 서로 기다릴 필요가 없다.
2. 체크박스를 채우고, **안 되면 "실패하면" 에 적힌 대로 그 자리에서 방향을 튼다.**
3. 오후에 30분 모여 인터페이스를 고정한다.
4. 저녁에 기획서를 확정한다.

담당 표기는 [장비 목록](../setup/host-inventory.md)의 PC 별칭이다. 마스터 1 = `master01`, 개인 노트북 = `dev01`-`dev04`.

## 확인할 네 가지

### 1. `hospital.usd` 가 Isaac Sim 5.1 에서 열리는가 — 마스터 1

에셋 경로는 버전마다 바뀐다. 계획은 `Isaac/Environments/Hospital/hospital.usd` 를 전제한다.

- [ ] 씬이 열린다
- [ ] 센서를 켠 상태에서 [RTF](../README.md#용어)(실시간 대비 배율)·GPU·VRAM을 적는다. 방 prim 비활성화 전/후 비교
- [ ] [구역 매핑](p3-project-plan.md#31-씬에셋-후보)의 구역이 실제 씬에 존재하고, 팔과 AMR 작업 공간이 겹치는 자리가 있다

**실패하면**: 씬을 바꿔야 하고 구역 매핑이 전부 폐기된다. 대체 씬 후보를 그날 정한다.
과부하면 방·센서·동적 객체를 줄여서 진행하되, 줄인 씬의 수치를 원래 병원 씬의 수치로 적지 않는다.

### 2. 집어지는가 — 개인 노트북 (제어 담당) **(최우선)**

파지가 시나리오의 중심이다. 여기가 무너지면 남는 게 배송뿐이다.

- [ ] **Surface Gripper 로 YCB 상자를 집어 올린다** — 이것부터
- [ ] 집은 상태로 로봇이 움직여도 떨어지지 않고, 놓았을 때 목표 자리에 실제로 안착한다
- [ ] 성공한 물품의 크기·질량·파지점을 적는다
- [ ] (여유가 있으면) Robotiq 2F-85 물리 그리퍼로 같은 것을 한다

**순서를 지킬 것.** 물리 그리퍼부터 붙들면 마찰·질량·grip force 튜닝에 하루가 간다.
Surface Gripper 로 파이프라인을 먼저 세우고, 시간이 남으면 업그레이드한다.
Surface Gripper 는 흡착 방식이므로 "물리 손가락 파지를 검증했다"고는 쓰지 않는다.

**실패하면**: 파지를 빼고 컨베이어·전달대 방식으로 시나리오를 재설계한다. 당일 결정한다.

### 3. 보행자가 라이다에 잡히는가 — 마스터 1 또는 개인 노트북 (Nav2 담당)

애니메이션 캐릭터에 collision 이 없으면 Nav2 가 보행자를 보지 못한다.
그러면 인터락과 「동적 대응」 항목이 통째로 날아간다.

- [ ] People 캐릭터를 씬에 놓는다
- [ ] `/carter_a/scan` 에 그 캐릭터가 점군으로 찍힌다
- [ ] 캐릭터가 움직이면 점군도 따라 움직인다

**실패하면**: 보행자를 collision 이 있는 동적 prim(움직이는 박스 등)으로 대체한다.
시각적으로는 덜 그럴듯해도 인터락 로직은 그대로 살릴 수 있다.

### 4. Carter 2대가 각자 돈다 — 개인 노트북 (Nav2 담당)

- [ ] 네임스페이스 `carter_a`, `carter_b` 로 분리된다
- [ ] tf 가 충돌하지 않는다
- [ ] 각각 Nav2 로 한 지점까지 주행하고, 명령이 그 로봇에만 간다

Multiple Robot ROS2 Navigation 튜토리얼 구성을 **그대로 복제한 뒤** 수정한다.
처음부터 직접 구성하지 않는다.

**실패하면**: 팔 + AMR 1대로 먼저 사이클을 닫고, 2대 분리는 별도 이슈로 남긴다.

### 5. 통신 기반 — 전원

- [ ] 각 PC 의 IP 가 [장비 목록](../setup/host-inventory.md) 표와 같다 (`.3`/`.4` 남은 PC 없음)
- [ ] 각 PC 의 `ROS_DOMAIN_ID` 가 115 로 동일하다
- [ ] 각 PC 의 `net.ipv4.ip_local_port_range` 하한이 40000 이다
- [ ] 마스터 1 의 `/clock` 이 나머지 PC 에서 보인다 (발행자 하나)

도메인 115 는 기본 ephemeral 포트 구간과 겹친다. 안 맞춰두면
"가끔 노드가 안 보인다" 가 나오고 원인 찾는 데 오래 걸린다 —
[네트워크 문서](../setup/ros2-wired-network.md) 참고.

## 저녁 — 기획 확정

스파이크 넷을 통과하면 [기획서](p3-project-plan.md)를 확정한다.
