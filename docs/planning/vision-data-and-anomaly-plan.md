## 3. #172 데이터와 라벨 규칙

### 3.1 첫 생성 대상

- 클래스는 `0: pouch` 하나다. 봉투의 QR 무늬는 class ID가 아니다.
- 운용 입력은 UR5 손 카메라다. 벨트 픽과 상판 봉투 선택 장면은 구분해 기록·평가한다.
- 학습 범위는 실제 운용 가능한 카메라 자세·봉투 위치·yaw·조명 변화에서 출발한다. 범위 숫자는 현장 카메라와 씬 설정을 읽어 PR-1 설정 파일에 기록한다. 이 문서에서 추측하지 않는다.
- 장면 변형은 물리적으로 가능한 배치인지 검사한다. 바닥 관통·공중 정지·의도하지 않은 카메라 시점이 섞이면 기록 후 제외하거나 별도 스트레스셋으로 둔다.
- 원본 annotation과 class mapping을 보존한다. instance/semantic ID를 배열 순서만 보고 YOLO class ID로 바꾸지 않는다.

### 3.2 박스 정책

첫 산출물은 이미지에서 보이는 봉투 영역의 tight 2D 박스다. 사용할 Isaac Sim 5.1 annotator 이름·필드·가림 의미는 PR-1에서 작은 장면으로 검증하고 버전을 고정한다.
가려진 전체 물체를 복원한 박스와 보이는 영역의 박스를 같은 정답 정의로 섞지 않는다.

| 입력 | 처리·시험 조건 |
| --- | --- |
| 정상 박스 | 이미지 경계 내 좌표를 실제 저장 RGB의 폭·높이로 정규화. 모두 finite, 중심은 0 이상 1 이하, 폭·높이는 0 초과 1 이하 |
| 화면 가장자리에서 잘림 | 경계로 자르고 `truncated` 기록. 면적 0이면 제거 사유 기록. 저장 RGB와 오버레이를 대조 |
| 부분 가림 | 가림 정도·라벨 포함 기준을 설정으로 기록하고 지표를 별도 집계. 최소 크기·가림 한계는 pilot에서 정한 뒤 acceptance 전에 고정 |
| 객체 없음 | 완전한 정답 검사 결과 빈 이미지이면 빈 라벨 파일을 정상 산출물로 보존 |
| RGB/annotation 누락·프레임 불일치 | 빈 이미지로 처리하지 않고 생성 실패로 기록. 검사 종료 코드는 실패 |
| NaN·잘못된 class ID·뒤집힌 좌표 | 조용히 정상화하지 않고 입력 오류로 보고 |
| resize/letterbox | 저장 이미지에 적용한 변환을 라벨에도 동일 적용. 원본 크기와 변환 기록 |

부분 가림·잘림 박스는 물체의 실제 전체 폭이 아니다. 현행 폭 기반 거리 추정에 이 박스를 그대로 연결해도 된다고 가정하지 않는다.
PR-3의 위치 오차 시험에서 유효 범위를 확인하고, 통과 전에는 해당 조건의 자동 파지 지원을 주장하지 않는다.

### 3.3 최소 데이터 manifest

아래는 후속 구현의 필드 요구사항이다. 현재 저장소에 이 형식의 검사기가 있다는 뜻이 아니다.

| 묶음 | 필수 기록 |
| --- | --- |
| 생성/촬영 식별 | dataset 버전, sample ID, 원본 URI·SHA-256, 생성/촬영 세션 ID, 에피소드 ID, split |
| 출처 | `synthetic_train` / `sim_runtime_capture` / `physical_capture`. 시뮬 런타임 녹화를 실물 데이터로 부르지 않는다 |
| 환경 | 코드 SHA, Isaac·Replicator·드라이버 버전, USD·텍스처 해시, renderer, 물리/렌더 timestep, seed와 실행 설정 |
| 센서 | 카메라 식별·자세·내부 파라미터·해상도, RGB와 annotation을 묶는 프레임 키 |
| 라벨 | class mapping 버전, annotator·좌표 규약, bbox, 잘림/가림과 제외 사유 |
| 변환 | 변환기 버전, resize/색공간 등 전처리, 원본과 파생 샘플의 연결 |

데이터·가중치·영상은 외부 저장소에 두고 Git에는 생성 코드·설정·작은 시험용 fixture·manifest 참조를 둔다.
원본과 산출물을 덮어쓰지 않으며, 중단 후 재실행에서 ID 충돌·라벨 없는 이미지를 탐지한다.
seed가 같다는 이유만으로 GPU 렌더 결과의 비트 단위 동일성을 보장하지 않는다.

### 3.4 분할과 비교

1. 원본 세션/에피소드 단위로 train/validation/test를 먼저 나눈다. 같은 장면의 연속 프레임과 파생 증강본은 같은 split에 둔다.
2. 그룹 ID 교집합과 이미지 해시 중복을 자동 검사한다. 서로 다른 seed만으로 누수가 없다고 판단하지 않는다.
3. 일반화 주장에 맞춰 배경·배치·조명·텍스처 등 holdout 조건을 추가한다. 같은 카메라·자산을 공유하는 것이 항상 누수는 아니지만, 그 조건 밖 성능을 입증하지는 않는다.
4. 모든 비교는 동일한 고정 test manifest를 사용한다. 모델 선택·threshold 튜닝에는 validation만 사용한다.
5. 비교마다 backbone/초기 가중치·입력 크기·증강·학습 스텝·학습 seed·연산 예산을 기록한다. 합성 데이터 효과를 주장할 때는 학습 예산을 맞춘 비교를 포함한다.
6. 실물 데이터가 없으면 합성 데이터 학습과 시뮬 런타임 holdout 평가까지만 보고한다. `Real Only / Real + Synthetic` 비교는 실물 수집 계획이 생긴 뒤 추가한다.

검출 평가는 precision·recall·mAP50·mAP50-95와 조건별 표본 수를 보고한다. 검출 confidence 운용점은 validation에서 고정한다.
학습 데이터에 randomization을 적용하지 않은 모델과 적용한 모델을 같은 운용 holdout에서 비교한다.
기존 color/QR 경로는 운영 기준선으로 별도 측정한다. YOLO 박스 평가와 QR 주문 일치율, 위치 오차, 첫 시도 파지 성공률을 한 정확도로 합치지 않는다.

## 4. #174 검사 의미와 오프라인 검증

### 4.1 검사 상태를 제한한다

첫 대상은 **벨트 끝에서 봉투가 정지하고 카메라가 정해진 검사 자세에 도달한 이미지**다.
정지·검사 자세 정보는 offline manifest의 검사 eligibility 정보로 기록한다.
봉투 위치·결함 ground truth는 독립 평가 정답으로만 사용하고 모델 입력에 섞지 않는다.

| 상태 | 기대 결과 | 분모 처리 |
| --- | --- | --- |
| 배출 전·픽 후 빈 벨트, 카메라 이동 중 | 검사 대상 아님 `not_applicable` | 발생 수는 기록하고 eligibility 규칙에 따라 검사 분모와 분리 |
| 검사 요청 시 봉투 없음 | 존재 검사 실패 `missing` | 이상 사례 분모에 포함. YOLO crop이 없다고 삭제하지 않는다 |
| 봉투는 있지만 검사 영역 밖 | 위치 검사 실패 `out_of_position` | 이상 사례 분모에 포함 |
| 영상 없음·가림 과다·입력 품질 불충분·추론 오류 | `unknown`과 사유 | 판정 불가 수와 coverage를 보고. 정상으로 합치지 않는다 |
| 유효 입력·허용 외관 | `normal` | 정상 사례 분모 |
| 유효 입력·정의한 외관 결함 | `anomaly` | 결함 종류별 분모 |

이 명칭은 오프라인 평가 레코드의 제안이다. 새 ROS enum이나 배송 종료 상태가 아니다.
결함 사례가 입력 품질 문제로 `unknown`이 되어도 전체 결함 분모에서 사라지지 않게 한다.

### 4.2 모델 앞에 간단한 기준선을 둔다

- 존재·위치는 고정 검사 영역과 단순 규칙 기준선을 먼저 평가한다. YOLO가 만든 crop만 입력하면 누락 사례를 평가할 수 없으므로 전체 검사 영역 경로를 유지한다.
- 외관 검사는 제한된 결함 두 종류부터 시작한다. 후보는 봉투 표면 이물과 외관 변형이며, 자산에서 실제로 표현 가능한지 먼저 확인한다. 표현되지 않는 파손을 검증했다고 쓰지 않는다.
- 정상 QR 내용 변화는 정상이다. 처음에는 QR 영역을 사전에 정한 전처리 규칙으로 제외하는 안과 다양한 QR을 포함하는 안을 validation에서 비교하고 하나를 고정한다. 제외한 영역의 결함은 검출 범위 밖으로 명시한다.
- 같은 외형의 다른 주문은 기존 QR 대조로 검출한다. 외관 모델은 약품 성분·내용물·주문 일치를 입증하지 않는다.
- 학습·validation에서 보지 않은 결함 종류를 별도 challenge set에 둘 수 있다. 그 결과는 해당 사례에 대한 결과이며 모든 미지 이상을 잡는다는 보장은 아니다.

### 4.3 모델·threshold 선택

먼저 기존 의존성과 실행 환경을 확인하고 단순 규칙 기준선 및 정상 데이터 기반 모델 하나를 같은 데이터로 비교한다.
모델 패키지·버전·라이선스·추가 설치·GPU 메모리·제거 방법은 PR-4에 적는다. 이 계획은 특정 라이브러리 도입을 확정하지 않는다.

- 정상 train으로 특징을 학습하더라도 이상 validation으로 threshold를 정했다면 그 사실을 보고한다. 전체 과정이 이상 사례를 한 번도 보지 않았다고 쓰지 않는다.
- score의 방향·raw/normalized 여부·정규화 통계·image/pixel threshold를 구별한다. 예시 숫자 0.60을 재사용하지 않는다.
- validation에서 전처리·모델·threshold를 정하고 묶음 버전/해시로 고정한다. test 데이터로 정규화 범위를 다시 계산하지 않는다.
- threshold 선택은 사전에 정한 오탐·미탐 비용/제약에 따른다. 라이브러리 기본 F1 최댓값이 프로젝트 요구를 충족한다고 가정하지 않는다.
- 기본 산출물은 image-level score와 판정이다. anomaly map은 오류 분석이 필요할 때 추가하며, pixel-level 성능 주장은 독립 mask 정답이 있을 때만 한다.

### 4.4 시험 결과의 단위

평가 단위는 검사 이벤트다. 연속 프레임 수를 독립 시행 수로 부풀리지 않는다.
프레임을 합쳐 이벤트를 판정한다면 집계 규칙도 validation 후 고정한다.

- 정상·결함별 N, false accept, false reject, unknown, coverage와 누락·실패 수.
- 알려진 결함과 holdout 결함 결과 분리. 오탐은 정상 검사 이벤트를 분모로 보고한다.
- 전체 결함 중 탐지 수를 함께 보고하여 unknown을 제외한 recall만 높아지는 것을 막는다.
- model-only 시간과 decode·전처리·대기·추론·후처리를 포함한 전체 wall 시간의 p50/p95, 최대값, GPU 메모리.
- 성능 비교의 불확실성은 이벤트/세션 단위로 평가한다. 같은 에피소드 프레임을 독립 표본으로 취급하지 않는다.

## 5. 구현 PR 순서와 통과 조건

PR 번호는 아직 없다. 아래 PR-1부터 PR-5까지는 작업 단위 이름이다.
각 PR은 이전 단계의 실제 결과를 입력으로 받으며, 구현하지 않은 항목을 체크 완료로 표시하지 않는다.

| 단계 | 변경 범위와 산출물 | 검증·다음 단계 조건 |
| --- | --- | --- |
| 이번 계획 PR | 이 문서와 문서 색인. 일곱 리뷰 지적을 범위·데이터·판정 규칙으로 반영 | 저장소 검사와 팀 리뷰. #172/#174를 닫지 않음 |
| PR-1: #172 소량 생성 | `sim/`의 독립 실행 생성기·설정·RGB/annotation 프레임 연결·manifest. 기존 배송 실행 진입점과 분리 | 마스터의 Isaac 5.1에서 정상·빈 장면·잘림·가림·QR 변화·중단/재실행 사례 생성. 샘플 수·시간·실패·출력 크기와 오버레이 확인 기록 |
| PR-2: #172 변환·분할 검사 | `sim/` 책임 안의 GPU 없는 순수 변환/검사 도구와 `sim/tests/` 시험. Isaac import는 생성 진입점에 한정 | 좌표 경계·NaN·class 불일치·크기 변경·RGB 누락·중복 그룹/해시·빈 라벨 구분 시험. 실제 PR-1 산출물도 읽어 통과 |
| PR-3: #172 학습·기존 노드 연동 | 버전 고정 학습 설정·평가 결과·모델 참조. `src/rokey_p3_perception/`에 단일 클래스 사전 검사와 필요한 최소 연결 | 독립 test의 검출 지표, YOLO 단독/폴백 포함 결과 분리. L2에서 모델 오류·빈 검출·class 부적합·기존 메시지 유지 검증. L3에서 위치 오차·파지 결과 및 기존 시나리오 회귀 확인 |
| PR-4: #174 오프라인 비교 | 고정 ROI의 데이터 manifest, 기준선·모델 하나·threshold/정규화 묶음, 이벤트 단위 평가 | 누락·다른 QR·가림·동일 외형 다른 주문·정상 위치 변동·추론 오류를 포함. 고정 test에서 기준선 대비 이득·오탐·unknown·시간을 보고 |

PR-1 설정/필드가 고정되면 PR-2의 순수 도구는 별도로 개발할 수 있다. PR-4는 YOLO 모델이나 PR-3 완료를 필수로 기다리지 않는다.
다만 공용 마스터 GPU 실행은 시연 검증과 겹치지 않게 예약한다. 모델 학습·생성 작업을 운영 launch에 넣지 않는다.
첫 단계별 시간 예산은 **작업일 1일 이내의 가능성 확인**으로 제안한다. 합격 날짜를 보장하는 추정이 아니며, 초과하면 미해결 원인과 추가 비용을 보고하고 범위를 줄인다.

권장 구현 위치는 책임 경계 제안이다. 새 ROS 패키지나 의존성을 선제 생성하지 않는다.
[일정](schedule.md)은 임재범의 부 담당 조각에 Replicator·YOLO 학습을 포함하고, [perception README](../../src/rokey_p3_perception/README.md)는 생성 스크립트를 simulation 소유로 설명한다.
이 계획으로 소유권을 몰래 변경하지 않는다. 임재범이 작업을 조율하고, `sim/` 변경은 simulation 담당, 인식 모델·노드 변경은 manipulation/perception 담당이 리뷰한다. 실제 작성자·PC는 각 구현 PR에 명시한다.

## 6. 아직 값이 없는 항목과 그것을 정할 단계

| 항목 | 결정 근거·담당 단계 | 결정 전 가능한 일 |
| --- | --- | --- |
| 카메라·씬·ROI·운용 변동 범위 | 현장 설정과 소량 샘플, PR-1·PR-4 | 생성/변환 도구 설계 |
| 최소 박스 크기·가림 한계 | 검출·위치 오차 pilot, PR-2·PR-3 | 경계 사례 수집과 정책을 받는 검사기 |
| 데이터량·독립 세션 수 | pilot 분산·생성 비용·필요 불확실성, 각 평가 protocol | 소량 pilot |
| 허용 false accept/reject·unknown, 지연 상한 | 사용 목적과 pilot 비용, PR-3·PR-4 이후 acceptance protocol | 기준선 수집·분포 보고 |
| 외관 결함 두 종류의 구체적 표현 | 실제 자산/촬영 가능성, PR-4 시작 시 | 정상 입력 수집 |

미정 숫자를 임의의 합격선으로 채우지 않는다. PR-1/2의 데이터 무결성 검사는 먼저 구현할 수 있지만, 성능 합격은 기준이 정해지기 전 주장할 수 없다.
acceptance는 [측정 정책](../policy/metrics.md)에 따라 별도 protocol을 고정·병합한 뒤 실행한다. pilot과 test를 이미 튜닝에 썼다면 새로운 holdout으로 다시 평가한다.

## 7. 중단·축소·완료 판정

- #172는 합성 데이터가 개선을 보이지 않아도 생성 파이프라인의 유효성·한계를 남길 수 있다. 다만 성능 개선 성공으로 보고하지 않는다. 운영 모델 교체는 별도 승인·검증 대상으로 둔다.
- #174가 단순 존재/위치 규칙보다 이득이 없거나 외관 결함이 관측 불가능하면 범위를 줄이거나 중단한다. 실패 결과도 포트폴리오의 비교 실험으로 남긴다.
- #174의 오탐·지연 비용이 높으면 오프라인 결과까지만 유지한다. 기본 배송·QR 검수 경로에 강제 연결하지 않는다.
- GPU 자원 충돌이나 일정 지연이 생기면 추가 기능 작업을 중지하고 기존 시연을 우선한다. 중단은 본 계획/이슈에 기록하며 목표 완료와 구별한다.
- #172 완료 보고는 생성·변환·검사·학습 연결·비교 결과와 미지원 조건을 갖춰야 한다. 실물 데이터가 없다면 이슈의 실물 비교 항목을 후속으로 명시적으로 분리한 뒤 범위에 맞춰 닫는다.
- #174 완료 보고는 정의한 검사 범위, 기준선 비교, 고정 평가, unknown/실패 처리와 기록 전용 연동의 실시/보류 결정을 갖춰야 한다. 광범위한 이상 검출 구현 완료로 닫지 않는다.

## 8. 검증 계층과 출처

이번 문서 PR은 저장소 검사 대상이다. 모델 학습·성능 시험, ROS L2, Isaac L3는 미실행이다.
후속 단계는 순수 도구 시험, ROS 통합, 마스터 시스템 시험, 별도 고정 데이터 평가를 구분해 결과를 남긴다.
원본 데이터와 모델 출력을 서로 독립 정답으로 순환 사용하지 않는다.

- [Isaac Sim 5.1 object-based SDG](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/replicator_tutorials/tutorial_replicator_object_based_sdg.html): 생성 구성의 참고. 프로젝트 장면·라벨 정책의 현장 검증을 대신하지 않는다.
- [Anomalib 2.4.0 후처리](https://anomalib.readthedocs.io/en/lib-v2.4.0/markdown/guides/how_to/models/post_processor.html): validation에서 threshold·정규화 통계를 구하고 시험에 적용하는 예. raw score는 모델별 범위가 다르다. 이 버전을 프로젝트에 설치했다는 뜻은 아니다.
- [배송 계약](../architecture/delivery-contract-v1.md): 시간·epoch·기존 인식 출력·실패 처리의 기준. 본 계획은 이 계약을 개정하지 않는다.
