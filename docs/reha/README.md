# 리하(리얼 하스피탈) 회차 기록

병원 월드 통합이 한 바퀴 돌면, 그때부터는 실습이 아니라 **리하**다. 병원 운영을 실제처럼 꾸리고 "실제처럼 돌아가는가"로 본다(#576, 재범 9/23).
회차 하나 = 파일 하나(`reha-NN.md`)다. 회차 원문은 #240에 둔다. 이 폴더는 그 원문을 회차 틀에 옮긴 기록이다. evidence 가 아니다.

> **상태: 기록(9/23–9/28).** 이 폴더의 파일은 회차 기록이라 본문을 고치지 않는다.
> 지금 상태(`v1.1.0`)는 [루트 README](../../README.md), 실행 절차는 [병원 전 구간 런카드](../runbooks/hospital-full.md)를 본다.
> 2026-09-30 파일 기준으로 리하11 은 없다. 9/29 작업(#784–#789)은 L3 전이다. 리하10 에 넣지 않았다([리하10](reha-10.md) 머리).

## 다섯 장면

한 바퀴를 다섯 장면으로 나눠 어디까지 닿았는지 적는다. 번호는 재범 결정 시나리오(#527 댓글 5790278911)의 ②–⑥이다. ① 웹 요청은 장면이 아니라 시작 조건으로 적는다.

| 장면 | 무엇 | 시작 → 끝 이벤트 |
| --- | --- | --- |
| ② 보충·약통 QR | M0609 가 약통 QR 을 확인하고 채운다 | `REFILL_REQUESTED` → `REFILL_DONE` |
| ③ A1 적재 | 조제 → 씬 컨베이어 → A1 롤러 끝 → 합본 UR5 가 봉투 QR 확인 뒤 트레이에 싣는다 | `DISPENSED` → `LOAD_DONE` |
| ④ 이동 | Nav2 로 병상까지 간다 | `DEPARTED` → `ARRIVED` |
| ⑤ 내려놓기 | 인식표 확인 뒤 보관함에 놓는다 | `AUTH_OK` → `ORDER_DONE` |
| ⑥ 복귀 | 도크로 돌아온다 | `RETURNED` → `DOCKED` |

재고가 충분하면 ② 는 일어나지 않는다. 그때는 "일어나지 않음"으로 적고 도달 실패로 세지 않는다.

## 판정 언어 — 다섯 단계(#610)

회차·기능마다 **어느 단계까지 왔는지**를 한 칸에 하나만 적는다. 단계를 건너뛰어 쓰지 않는다.

| 단계 | 뜻 |
| --- | --- |
| 코드 작성 | 커밋이 있다. 시험은 아직이다 |
| CI 통과 | L1·L2(colcon·sim/tests·저장소 검사)가 그 SHA 에서 초록이다 |
| L3 관측 | Isaac 회차에서 그 장면이 보였다(원문 #240 ID). 판정선 칸이 다 채워졌다는 뜻은 아니다 |
| 계약 합격 | 결과 전에 고정한 판정선의 **모든 칸**이 원문으로 채워지고 넘었다 |
| 발표 증거 | 계약 합격 + 영상·원본 해시가 있어 #527 에 올렸다 |

회차는 **SHA 별로 나눠 적는다.** 여러 SHA 를 "n회 연속"으로 합치지 않는다.

## 규칙(#576)

- 창 모드·전체 한 바퀴만 돈다. 부분 회차·headless 는 리하 회차가 아니다.
- 판정선은 결과 전에 #240 에 고정한다. 결과를 보고 고치지 않는다.
- 회차가 끝나면 5줄 보고를 #240 에 올린다. 이 폴더의 `reha-NN.md` 는 그 뒤에 채운다.
- 빈칸은 비우지 않는다. **미실행**(돌리지 않았다) / **보고되지 않았다**(받지 못했다) / **일어나지 않음**(조건이 안 됐다)으로 구분해 적는다.
- 최종 촬영 회차는 `P3_RENDER_MAX=`(빈 값, 렌더 상한 해제)로 띄운다([병원 데모 런북](../runbooks/hospital-demo.md)).
