# 챌린지 리포트 ② 골격 — 병원 시뮬을 실시간 가까이: rtf 0.34 → 0.69

> 평가 3.7 "성능 개선을 위한 다양한 시도 기술 리포트"에 낸다. 9/28 에 자리표시를 채웠다. 아직 비는 곳은 6절에 적는다.
> 첫 리포트는 [병원 Nav2 1→7회차](challenge-hospital-nav2.md)다. 이 문서는 두 번째다.
> 수치는 모두 #240 원문·`docs/reha/`·`docs/analysis/` 에서 옮긴다. **장비가 다르면 rtf 를 비교하지 않는다** — 표는 장비별로 나눈다. 해석은 "해석"이라고 적는다.

## 1. 문제

병원 전 구간 한 바퀴가 벽시계로 10 분 넘게 걸렸다. rtf 0.3–0.4 에서는 촬영·반복 측정이 어렵고, 제어 주기가 밀려 팔·주행이 시한을 넘긴다(리하01 `grasp_pose` 실패).

- 제목의 "0.34 → 0.69" 는 두 장비의 숫자를 섞은 것이다. 말할 때는 **장비가 다르다**고 같이 말한다.
- 판정선(5/5 · touch 0 · DELIVERED)을 지키면서 빨라졌다: reha-04 master02 N=2 는 5/5 · touch 0 · rtf 0.429 다. reha-05 골든-2(`138cbac`) master02 계약 합격 rtf 는 0.550 이다. master01 회차24 rtf 는 0.676 이다([리하 README](../reha/README.md) 04 · 05행).
- 판정 구성(더미 · 보행자 · 비전 · 녹화 ON)에서는 더 낮다. v1.0 회전 7(`9760d9d`, master01) 14 attempt 가 모두 PASS 다. touch 는 0 이다. rtf 는 0.457–0.601 이다([v1.0.0 배포 기록](../../evidence/deployments/2026-09-28-jaebeom-v1-0-0.md), `evidence/runs/20260928*` · notes `campaign r7`). 골든 0.69 와의 차이를 무엇이 만드는지는 재지 않았다(미확인).

## 4. 곁가지 발견 — 감속기

속도가 붙자 감속기가 필요해졌다. 감속기를 고치며 한 층씩 드러난 것을 문제→가설→결과로 적는다(본문).

1. 코스트맵을 한 장도 못 받는다 → QoS(래치) → 1 s 재발행(#240 5795827276)
2. 받는데 늘 50 % → 팽창 띠 99 를 장애물로 셌다 → LETHAL 100 만(`4d01333`)
3. 여전히 `여유 모름` → 로컬 코스트맵이 `/amr_1/local_costmap/scan` 을 구독(아무도 안 냄) → scan 토픽 수정 `138cbac`(#620) → 골든-2 로 확정. 감속기 전환이 master02 29회 · master01 53회 관측됐다([리하 README](../reha/README.md) 05행, [reha-05](../reha/reha-05.md) A)
4. 정지 규칙(긴급정지 감지)은 아직 안 된다 → 진단만 했다(#752). 수정은 v1.0.1 로 미뤘다([v1.0.0 배포 기록](../../evidence/deployments/2026-09-28-jaebeom-v1-0-0.md) "알려진 미해결")

## 5. 한계 — 숨기지 않을 것

- rtf 는 1.0 에 못 미친다. 영상은 배속으로 보여 주고 화면에 적는다.
- 장비마다 값이 다르다(같은 SHA 도 master01 이 높다). 원인은 미확인이다.
- GPU 전력 상한 80 W 는 바꿀 수 없다(`docs/analysis` "전력 상한 not supported", #575).
- 회차 수가 적다(변수마다 1–2 회). 분산은 말하지 않는다.
- 감속기 정지 규칙은 v1.0 에서 미수정이다(#752, v1.0.1).

## 6. 아직 비는 곳

- 1번 시도의 같은 장비 전후 rtf — 그런 회차가 없다(미확인)
- 각 시도의 회차 폴더 · SHA256SUMS — 출처 칸의 #240 원문에 있다. 이 문서로 옮기지 않았다
