- 영상 구간 합: 3a–3g 113 s + 9a–9e 45 s = 158 s. 슬라이드 142 s.
- 3b 는 [촬영 계획](hospital-demo-shotlist.md) 2-4절(재범 9/25) 대로 **배속 없이** 길게 둔다. 한 동작(잡기 → 넣기) 안에서는 자르지 않는다. 50 s 가 넘치면 round 보충만 남긴다. module 은 넣는 순간 8 s 만 쓴다.
- 9b 배속 ×470 = 5,617 s ÷ 12 s ≈ 468 을 올림. 화면에 배속을 크게 둔다. 이 구간 길이를 사이클 시간으로 말하지 않는다.

## 3. 화면 표기 규칙

- 첫 화면: "서로 다른 run 6개(L1 · S11 · S23 · T10 · PS · N2)를 이어 붙였다. 각 컷의 run ID 는 끝 화면에" 를 적는다.
- 끝 화면: 1절 표(약호 · run_id · sha256 앞 16자)를 그대로 띄운다.
- 배속 구간은 `×N` 을 계속 띄운다. 1× 구간은 표기하지 않는다.
- 자막에 쓰지 않는 말(과장 위험, 근거는 [tech-3 근거](tech-3-sources.md) 4절): "카메라로 봉투를 집는다" · "카메라로 환자 인증" · "로봇이 배송 성공을 판정" · "조제기가 조제한다" · "AMCL/SLAM" · "긴급 주문이 진행 중 배송을 선점" · "MoveIt · YOLO" · "다중 PC 로 v1.0 검증".
- 실패 장면은 영상에 넣지 않는다. 실패는 10번 슬라이드 표로 모두 보인다([촬영 계획](hospital-demo-shotlist.md) 6절).

## 4. 아직 안 된 것

- 편집본: 미실행. 편집자와 편집 도구가 정해지지 않았다.
- 각 컷의 녹화 안 시각(초): 미확인. run 폴더 `events.jsonl` 의 이벤트 wall 시각으로 찾는다.
- 리허설 시간 기록(평가 123행): 미실행.
- 본촬영 여섯 앵글 테이크로 바꿀지: 재범 결정. 바꾸면 3b · 3d · 3e 의 출처만 바꾼다. 시간표는 그대로 둔다.
