## 판단

저부하 장면과 병원 장면의 역할 분리, 상대 목표 계산, 같은 상위 로직 재사용은 채택한다.
그러나 원안은 Gazebo/SDF, 별도 주문 FSM, 신규 토픽을 전제로 하므로 현재 프로젝트에 그대로 적용할 수 없다.
좌표 이식은 이미 #215로 구현됐으며, 다음 문제는 **어느 합성 장면·벨트·지도·관측을 함께 검증할 것인지**다.

## 이미 있는 이식 경로

[sim/README](../../sim/README.md)의 `hospital-v2`와 [base_scene.py](../../sim/standalone/p3sim/base_scene.py)는 다음 결정을 구현한다.

1. 세준 병원 USD를 `/World/P3Base/Scene`에 참조한다.
2. wrapper에 조제실 원점의 역변환을 적용해 기존 레일·팔·벨트 작업 좌표를 유지한다.
3. M0617·겹치는 prim·병원 벨트 그래프를 끄고 기존 M0609와 단일 벨트를 사용한다.
4. `/clock`은 실행 스테이지 하나가 소유한다.

결정 근거는 #215 대화 중 재범의 2026-09-18 결정 기록을 따른다.
Isaac 병원 이식 L3는 main 설명상 미실행이다. usd-core 정적 겹침 결과를 Isaac 충돌·주행 합격으로 승격하지 않는다.

## #233을 합칠 때 새로 필요한 경계

세준 PR #233은 병원 분기 벨트를 쓰는 별도 실행기다.
현재 HEAD의 `hospital_main.py`는 `/isaac/conveyor/route` Int32를 받아 방향을 바꾸고 같은 `/World/Cube_01`을 시작 pose로 되돌린다.
요청 ID·epoch·취소·배송용 BeltState 연결이 없는 수동 반복 시연이다. 속성 readback은 물리 출구 도달 관측이 아니다.

따라서 통합은 두 층으로 나눈다.

- **배경 이식:** 기존 `hospital-v2`로 회귀를 확인. #233 병원 벨트를 동시에 활성화하지 않음.
- **벨트 교체:** 세준 벨트를 배송 제어 아래 넣는 별도 후속 PR. 출구-적재 위치 매핑, 점유·끝 정지 관측, 주문 식별, reset/epoch, 명령 중 소포 텔레포트 금지부터 계약화.

#236 리뷰는 #233의 이전 `3332bbd`를 대상으로 한다.
최신 `b9ba0d6`의 USDA에는 `ROS2PublishClock`, `m0617`, `Downloads` 문자열이 없고, 자산 경로는 호스트 설정을 요구한다.
따라서 이전 리뷰의 clock·호스트 기본 경로 지적을 현 HEAD의 미수정 결함으로 반복하면 안 된다.
반면 수동 route 명령과 배송 제어의 차이는 남는다. 변경된 벽·prim은 원점 A의 겹침 및 비활성 목록을 다시 검사해야 한다.

## 수치 기준에서 먼저 고칠 것

문 폭 0.9 m에 좌우 0.15 m 여유를 요구하면, 불확실성을 무시해도 전체 통과 폭은 0.6 m 이하여야 한다.
현재 Nav2의 반경 0.6 m 표현은 직경 1.2 m이므로 해당 문을 통과할 수 없다.
이 값은 임시 설정이며 실제 Ridgeback 폭을 측정했다는 뜻은 아니다. 팔 수납·상판·적재물을 포함한 실제 footprint로 다시 판정한다.
[Nav2 Jazzy 튜닝 안내](https://docs.nav2.org/jazzy/configuration_and_development/tuning_guide/)도 비원형 로봇의 실제 polygon 사용을 권한다. inflation 조절로 물리 간섭을 해결하지 않는다.

USD 추출 1 mm는 정적 변환 검증 목표이지 AMCL 또는 물리 도킹 정확도가 아니다.
도킹 후보 0.05 m / 0.05 rad는 실제 최종 goal checker, 독립 위치 관측, 정착·불확실성 기준과 함께 검증해야 한다.
라이다 반사 필터도 센서 종류·재질 모델·실제 오관측을 확인한 뒤 적용한다. 보이지 않는 벽을 필터로 지워 통과시키지 않는다.

## 검증 범위와 남은 입력

확인: main 및 두 PR의 소스·문서 정적 대조, OpenUSD/Nav2/Isaac 공식 문서 조회.
미실행: 병원 자산 전체 로드, Isaac 실행, AMCL, 실제 도어 폭·로봇 형상 측정, RTF 비교, 피킹·배송 L3.

다음 구현 전에 필요한 입력은 활성 병원 scene/자산 버전, 세준 벨트 채택 시점, 모바일 UR5 장착 정보, 앵커 바인딩, 지도 및 실측 공차다.
모르는 좌표를 예시 숫자로 채우지 않는다. 구체적 수집 담당·선행 조건·산출물은 후속 통합 계획에 둔다.

## 후속 지시문: 컨베이어 CPS와 분산 충전

사용자 제공 최종 지시문을 추가 대조했다. #238 초안은 분기 벨트 교체 계약을 다뤘지만, **기존 벨트부터 필요한 도착·정착·피킹 허가·다음 배출 조건을 충분히 분해하지 못했다**.
[CPS 보완 계획](../planning/conveyor-cps-integration-plan.md)에 현행 소스, 내부 상태도, 정지 거리/관측 예산, 수정 위치와 실패 시험을 추가한다.

- 기존 `BeltModel`은 물체 pose·속도 기반 종단 정지를 이미 구현한다. “로직 전무” 또는 “타이머 구동뿐”이라는 판단은 부정확하다.
- `at_end`는 독립된 벨트 정지 관측이 아니며, stage의 물체/속도 관측 누락·이탈·timeout과 실제 픽 직후 점유 해제 경로를 보강해야 한다. GT 감지와 영상 인지 성공도 구분한다.
- 감지 후 STOP 발행만으로 충분하지 않다. 실제 정착, 정지 후 새 QR/pose, 실제 attachment, 지정 상판 칸 안착, 팔 통로 이탈 및 유효한 벨트 비움까지 확인한다.
- 약 제조·패키징 물리 구현 제외는 현행 blackbox와 일치하지만 주문·재고·M0609 보충·조제 재개까지 삭제하는 뜻은 아니다.
- 분산 무선 충전·배터리 배차는 현행 조제실 밖 대기 독·복귀 순서 배차·배터리 모델 없음과 다른 범위다. 별도 결정 전에는 기존 시나리오와 공식 일정을 바꾸지 않는다.
- 원본 CAD 원점 강제, 물리 없는 피킹 검증, SDF 추출, 도착만으로 배송 완료, 무조건 inflation 축소는 이전 검토의 수정 판단을 유지한다.

이 후속 변경은 계획 문서다. 제품 코드의 예방 조치가 이미 반영되었다거나 실제 CPS 시험이 통과했다고 주장하지 않는다.

## 후속 지시문: 기능 통합 F와 리소스 최적화 O

사용자의 새 2단계 가이드와 #238의 결정 총괄 댓글을 반영하여 [적용 계획](../planning/integration-resource-two-phase-plan.md)을 추가했다.

- 기능·계약 고정 후 최적화는 채택. 다만 측정과 필수 deadline 검사는 F부터 수행하며 부하 때문에 기능 검증이 안 되면 먼저 분리 수정한다.
- 임재범이 구조·코어·최종 결정을 총괄한다. 이 검토의 후속 구현은 골격 인계 후 배정 단위 구현·정합에 한정한다. 기존 팀별 질문은 재범 취합으로 수정했다.
- 기존 통합 4단계는 F의 세부 WBS로 유지하고 O를 후속 비교/회귀 단계로 추가했다. P7 운영 아키텍처 전환과 구분한다.
- 반복 제시된 분산 충전·예약은 이제 신규 F4 목표로 추적한다. 앞 절의 “별도 결정”은 실행 배치·정책·계약이 아직 필요하다는 의미로 좁힌다. 현재 실행 기본값이 변경되거나 코어가 구현됐다는 뜻은 아니다.
- Gazebo 튜닝은 Isaac/PhysX 기준으로 고쳤다. `pharmacy_stage.py`의 render dt 기반 동작·timeout 계산과 loop 뒤 벨트 관측 때문에 주기만 바꾸는 최적화도 동작 회귀가 필요하다.
- 센서/Costmap 주기를 낮추면 반응이 늦어질 수 있다. 내부 update와 topic publish를 구분하고 측정된 병목만 바꾼다. RTF·FPS·관측 age·제어 지연·기능 결과를 별도 판정한다.

근거는 같은 런타임 소스와 Isaac 5.1 / Nav2 Jazzy 공식 문서다. 최신 main `427c3e3`의 추가 변경은 발표 자료이며 이 분석의 런타임 소스와 충돌하지 않는다. 장비 계측·설정 튜닝·신규 모듈 구현은 미실행이다.
