(2) 작성자 외 검토자가 원본·실패 누락·시행 중복을 확인하고 review 를 남긴다(발표 작성 → 격리 검증 확인). (3) 동일 다중 PC 시행은 canonical run 1개로 묶는다. 모르는 값은 N/A 로 꾸미지 않으며 기존 run·frozen protocol 을 수정하지 않는다. 정정은 supersedes 규칙. (4) 예: rc2 원문(#240 5804528593)은 도구 10/10 delivered **및 접촉 1**, rc3 원문(5805153340)은 **9/10 및 접촉 0** — 둘을 합쳐 "10/10·접촉 0"으로 만들거나 도구 PASS 를 계약 합격으로 올리지 않는다.
