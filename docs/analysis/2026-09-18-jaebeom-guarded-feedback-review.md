# Guarded 모듈 피드백 8개 항목과 기본 활성화의 연쇄 영향

요청자: 임재범. 상태: **unreviewed — 수정 후보, Isaac L3·실기 미실행**.
기준: #229 병합 main `0baef8388a1472f3487b87150e55b0ba76926dac`.
#230의 기본 활성화 변경은 별도 PR이며, 이 수정은 main에서 분기해 기본값을 바꾸지 않는다.
검사는 2026-09-18 새 Python 프로세스에서 실행했다. 실행 노드·계획 캐시는 재사용하지 않았다.
아래 수치는 클라우드의 순수 Python/노드 대역 재현이며 마스터 장비 관측이 아니다.

## 항목별 판단과 처리

| 항목 | 확인한 동작 | 처리 |
| --- | --- | --- |
| 1. 0.5초 뒤 holding 소실 | `M0609ArmNode._on_holding()`은 **토픽을 받을 때마다** `Feedback.grip()`을 호출한다. 브리지는 holding을 주기 발행한다. 명령 때만 갱신한다는 전제는 맞지 않는다 | 시간 만료를 유지한다. 실제 콜백에 0.1초 간격으로 25회 같은 true를 넣으면 계속 유효하고, 수신을 0.6초 끊으면 unknown인 것을 검사한다 |
| 2. 최초 holding 미수신으로 즉시 실패 | 초기 `wait_until`도 `stop(False)`를 먼저 호출해 관측을 기다리기 전에 실패했다 | **수정**: 최초 명령 전 최대 5 wall s 동안 신선한 팔·레일·빈손 관측과 홈 정착을 기다린다. 취소·리셋·장면 무효·기존 fault는 계속 즉시 처리한다. false를 가짜 관측으로 주입하지 않는다 |
| 3. 종료 관측 없음 → `after=inf` | 기존에도 5 wall s 확인 시한과 관측 소실 검사로 빠져나오므로 무한 루프는 아니다. 다만 inf는 도달 불가능한 정착 조건이고 `latest()`를 두 번 읽는 경쟁이 있었다 | **수정**: 종료 관측을 한 번만 읽고 없으면 해당 축의 구간 종료 관측 누락으로 실패한다. `-inf`로 바꿔 이전 정착 이력을 통과시키지 않는다 |
| 4. stale 상태에서 hold 누락 | 신선한 현재 위치가 없으면 위치 hold를 보낼 수 없었다. `send()`가 false를 반환해도 진단하지 않았다 | **진단 보완**: 축별 미전송·거부·예외를 fault에 남긴다. 오래된 측정 좌표는 되돌림 이동을 유발할 수 있어 재전송하지 않는다. 통신 단절 시 물리적 정지를 보장하는 로컬 stop/watchdog는 여전히 후속 범위다 |
| 5. 이송 중 미세 진동으로 허위 인터록 | 실제 진동 자료가 없으며 기존 검사는 허용 범위 안의 위치·저속만 요구한다. 그 범위를 넘는 운동을 정상이라고 판단할 근거가 없다 | 임계값·고정 축 정착 조건을 유지한다. 추가로 발견한 실제 `JointState.velocity` 무시 문제를 수정한다. L3에서 고정 축 위치·속도·발생 빈도를 먼저 측정한다 |
| 6. 목표 잔차로 다음 구간 잠김 | 예시의 팔 잔차 0.0015 rad는 기존 허용 오차 0.0025 rad 이내다. 레일 잔차 0.0005 m도 0.001 m 이내다 | 두 경우 모두 **기존 계획 목표 그대로 정착 통과**하는 회귀 검사를 추가했다. 측정값으로 목표를 재설정하면 계획 경로에서 누적 이탈을 숨길 수 있어 적용하지 않는다 |
| 7. 작은 dt에서 수치 속도 급증 | 정지 좌표에 1e-6 rad 잡음과 1e-8 s 간격을 넣으면 정착이 거부됐다 | **수정**: 차분 속도는 1e-4 s 이상 떨어진 관측까지 간격을 합쳐 계산한다. 모든 중간 관측의 위치·전달된 속도 제한은 계속 검사하며, 초소형 간격의 큰 이탈도 거부한다 |
| 8. 모든 구간의 0.2초 대기 | 모든 보간점에 대기하는 것은 아니다. 한 Segment 안의 점은 연속 스트리밍한다. 주요 모션 Segment 경계에서 정착을 확인한다 | 축 전환·파지·해제·성공 판정 경계의 검사는 유지한다. 같은 축의 연속 구간 결합은 재시간화·충돌 재검사와 택트 측정이 필요한 별도 최적화다 |

`hold`는 소프트웨어 위치 명령 요청이다. 전송 성공이 제어기의 수락·정지 완료나 안전등급 E-Stop을 뜻하지 않는다.
4번은 진단 개선이며, 피드백이 사라진 축의 실제 정지를 구현했다고 주장하지 않는다.

## 연쇄 점검에서 추가로 재현한 결함

### 브리지의 초 경계 직렬화 → 허위 시간 역행 → 지속 fault

`RosBridge.publish_joint_states()`와 `publish_rail_states()`는 반올림한 nanosecond에 나머지 연산만 적용하고
초 올림을 누락했다. 실제 발행 메서드에 메시지/발행기 대역을 붙여 다음을 재현했다.

| 입력 sim s | 수정 전 메시지 | 수정 후 메시지 |
| --- | --- | --- |
| 1.9 | sec=1, nanosec=900000000 | 동일 |
| 1.9999999999 | **sec=1, nanosec=0** | sec=2, nanosec=0 |
| 2.0 | sec=2, nanosec=0 | 동일 |

수정 전 두 번째 관측에서 `feedback clock regressed; reset required`가 래치됐고, 다음 정상 관측으로 풀리지 않았다.
두 발행기가 기존 `p3sim.bridge.stamp()`를 재사용하도록 수정했다.
실제 Isaac의 시간값에서 이 부동소수점 경계가 얼마나 자주 나타나는지는 미측정이다.

### 전달된 실제 속도 무시 → 정착 오판정

브리지는 `JointState.velocity`를 발행하지만 노드가 값을 버리고 위치 차분만 사용했다.
같은 위치의 30 Hz 관측에 팔 0.1 rad/s·레일 0.02 m/s를 넣어도 두 축이 정착한 것으로 판정됐다.
이 입력은 위치 샘플 사이의 진동이나 상충하는 관측을 흉내 낸 합성 재현이며 실제 진동 측정은 아니다.

수정 후 관절 이름에 맞춰 velocity를 정렬하고 유한한 값·차원을 확인한다.
정착 창 안의 실제 속도와 위치 차분을 모두 검사한다. ROS 메시지에서 velocity가 생략된 경우에는 위치 차분을 사용한다.
NaN·잘못된 배열 길이가 있으면 해당 축의 관측을 무효화한다.

## 별도 수정·L3 측정이 필요한 연결

| 우선순위 | 연결과 확인 결과 | 다음 작업 |
| --- | --- | --- |
| 높음 | `_plan_cell()`은 캐시 조회·저장만 잠근다. 동일 칸을 precompute와 goal 스레드가 동시에 요청하면 계획 함수가 2회 호출됨을 장벽 대역으로 재현했다 | 장면·칸별 진행 중 계산 공유, 취소 가능한 계산 예산, 종료·리셋 시 작업 세대 무효화를 묶어 설계한다 |
| 높음 | 기본 fixture `upper_right/r0c0`, 기본 후보·12개 IK 시드 계산은 이 클라우드에서 90 wall s 안에 반환되지 않았다(아래 명령 종료 124). 계산 실패나 Isaac 90 sim s 초과를 증명한 것은 아니다 | 16칸의 전체 기본 후보 계산 시간을 측정한다. `tools/demo_v2.sh`는 `v2 계획 캐시: 16/16칸`을 최대 420 wall s 기다린다. 일부 칸의 거부와 준비 시간 초과를 구분해야 한다 |
| 높음 | 50 Hz 계획의 301개 점, 명목 6.0 s를 실제 `_stream()`에 넣고 60 Hz 또는 30 Hz 시계를 재생하면 모두 **10.0 sim s**가 걸렸다. 점은 생략되지 않았다 | 명령 주기·시계 양자화·센서 대기를 포함한 보수적 소요시간을 계산한다. 팔 90 sim s, orchestrator 90 sim s, soak 120 wall s 시한을 함께 검토한다. 팔 시한만 늘려도 orchestrator가 먼저 취소한다 |
| 높음 | 원격 feedback이 사라졌을 때 위치 명령만으로 현재 위치의 정지를 보장할 수 없다 | 브리지/제어기 로컬 stop·명령 만료 watchdog·정지 확인 계약을 별도 구현한다. 오래된 좌표 재전송으로 대체하지 않는다 |
| L3 | 실제 드라이브 추종 잔차·진동·관측 간격과 파지 물체의 접촉·미끄러짐은 이 검사에서 측정하지 않았다 | 모든 모듈 칸, 원통↔모듈 교대, 시작 지연, 피드백 단절, cancel/reset, 해제 실패를 포함한 실행 로그를 수집한다 |

기본 후보 계산 재현 명령(제어기 연결·ROS·Isaac 없음):

```bash
timeout --signal=TERM 90s env PYTHONPATH=src/rokey_p3_manipulation \
  python3 -u -m rokey_p3_manipulation.module_path \
  src/rokey_p3_manipulation/test/data/pharmacy_v2.json \
  src/rokey_p3_manipulation/config/m0609_collision.yaml \
  src/rokey_p3_manipulation/config/m0609_rail_teach.yaml \
  --cell upper_right/r0c0 --seeds 12
```

정상 피킹의 `present` 변경은 경로 서명에서 제외하므로 그 변화만으로 실행이 중단되지 않는다.
형상·좌표 변경은 서명을 바꿔 실행을 차단한다. 기존 회귀 검사와 발행 코드를 함께 대조했다.
`tools/demo_v2.sh`는 노드 기동 로그만 보고 보충을 시작하지 않으며 전체 캐시 준비를 기다린다.

## 검증 기록

수정 전 새 검사 묶음에서 executor/노드 검사는 **8 failed, 20 passed**였다.
브리지 검사는 **62개 실행, 두 publisher subtest 실패**로 초 올림 누락을 재현했다.
추가로 `/clock`이 늦게 한 번 갱신된 뒤 멈추는 경우, `_poll()` 내부에서도 확인 시한을 검사하도록 보완했다.
수정 전 전용 검사 **1 failed**였으며 초기 5 wall s 시한이 폴링의 별도 4초 상한 때문에 늘어나지 않게 했다.
추가 콜백·속도 입력 검사를 포함한 수정 후 결과와 전체 패키지·ROS CI 결과는 수정 PR 본문에 기록한다.
기존 상태 만료·진짜 시계 역행·리셋 울타리·파지 및 해제 확인·충돌 여유·속도/가속 기준을 유지한다.
