## 결론

1. **"가능 속도" 의 기준이 있는 것은 M0609 뿐이다.** 두산 사양(관절 150/150/180/225/225/225 °/s, TCP 1.0 m/s)이 저장소에 있고, 지금은 그 80% 다. 90% 로 올리는 것은 값 하나씩이다.
2. **AMR 의 "가능 속도" 는 팀이 Nav2 상한으로 잡아 왔다.** `navigation_params.yaml:34-38` 은 추종기 값을 "Nav2 상한의 80%(재범 9/21 \"AMR 합본은 최대의 80%\")" 로 정했고, Nav2 값은 태규님 실측을 반영한 상한이라 적었다(Ridgeback 제조사 1.1 m/s 는 근거로 쓰지 않음). 그 기준이면 90% 목표는 **추종기 0.9 m/s·0.9 rad/s·가속 0.9 m/s²·1.8 rad/s²** 다. 지금 추종기(0.4/0.8)는 Nav2 가 0.5 였을 때의 80% 라 **낡았다**. 최고 속도(Nav2 1.0)는 그대로 두고 — 1.5 는 적재 자리 touch 로 되돌렸다 — 평균을 막는 것은 감속기 근접 50% 와 추종기다.
3. **UR5·레일·회전·벨트·트레이는 사양 근거가 저장소에 없다.** 90% 목표를 정하려면 기준값부터 정해야 한다(재범 결정). 트레이는 마찰 재질조차 없어, AMR 가속을 올리기 전에 보유력부터 재야 한다.

## 실행 순서 제안

각 단계는 골든 위 **1변수 exp** 다. 두 마스터에서 판정선(런카드 3절 다섯 장면 + 주행 touch 0 + 해당 단계의 추가 판정)을 통과하면 승격한다. 회차 배정은 RC-2·증거 회차 뒤에 한다.

1. **팔 90% (밀림과 무관).**
   - 1a. M0609 관절 80→90%, TCP 0.8→0.9 를 한 exp 로(같은 "사양의 몇 %" 한 변수). 추가 판정: 보충 두 번의 `refill_ros released` 시각이 줄었는가, 놓기 오차·약통 낙하 0, `rail_follow worst_m`. 계획 캐시가 한 번 다시 풀린다(첫 기동 +73 s).
   - 1b. 레일 0.8→0.9 는 사양이 없어 **기준 결정 뒤**. 결정 전엔 하지 않는다.
   - 1c. UR5 는 기준(사양)을 먼저 정한다. 정하면 0.5 rad/s 에서 단계적으로(예: 0.5→1.0) 올리고 봉투 낙하 0 을 본다.
2. **트레이 보유력(G7).** 올리기 전에 잰다. 추종기 가속·Nav2 가감속을 한 단계 올린 회차에서 봉투 변위(트레이 자리 대비)를 기록하는 줄이 필요하다. 마찰 재질(봉투·트레이 physics material)을 넣을지는 `sim/` 쪽에서 판단한다. 이 단계가 끝나야 3·4 로 간다.
3. **AMR 직진.** 최고 속도(1.0)는 두고, 평균을 올리는 쪽이다.
   - 3a. 추종기 `follower_max_linear` 0.4→0.9, `follower_max_accel` 0.8→0.9, `follower_slow_radius` 0.667→1.5(비 0.6/s 유지, 도착 정밀도 조건 `navigation_params.yaml:43-44`). 낡은 80% 주석을 Nav2 1.0 기준 90% 로 고친다. 판정: 정차 d_xy ≤ 판정선, 트레이 밀림 0. 한 번에 두 배가 넘으니 0.4→0.6→0.9 두 단계로 나눌 수도 있다.
   - 3b. 감속기 근접 50%→60% 또는 near 1.0→0.9. 판정: 문·적재 자리 touch 0, 복도 시간.
4. **AMR 회전.** 0.4/0.8 실험(`195470e`) 결과를 먼저 본다. 밀림이 없으면 0.8/1.6 을 거쳐 0.9/1.8 로 간다. Nav2 `max_vel_theta` 는 관측 각속도 절대값 1.501 이 이미 상한 1.0 을 넘는 것부터 원인을 본다.
