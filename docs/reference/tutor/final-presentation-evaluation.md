## 2. 발표 방식과 배점

원본 상단 안내:

>
> 기능을 직관적으로 확인할 수 있는 영상 및 편집 필요!

| 평가 항목 | 배점 |
| --- | ---: |
| 디지털 트윈 설계 및 납품 품질 | 20점 |
| 시뮬레이션 환경 구성 | 10점 |
| 개별 로봇 제어 | 25점 |
| AI 비전 인식 및 활용 | 10점 |
| 시스템 통합 및 동적 대응 검증 | 35점 |

110점을 임의로 100점으로 환산하거나 챌린지를 별도 가산점으로 단정하지 않는다.

## 3. 평가 항목별 세부 기준 — 원문 전사

### 3.1 디지털 트윈 설계 및 납품 품질 — 20점

현실 문제를 시뮬레이션으로 재현하는 설계의 타당성과, 제3자가 git clone만으로 재현할 수 있는 납품 완성도를 평가한다.

- **문제 정의**: 해결하려는 현실 문제와 디지털 트윈으로 검증해야 하는 이유가 명확히 서술되어 있다.
- **현실 반영도**: 다중 로봇 작업 흐름이 실제 현장을 반영하고, 검증 목표(성공률, 한계)가 정의되어 있다.
- **저장소 완결성**: 실행에 필요한 모든 파일과 버전·패키지·환경 변수가 저장소에 문서화되어 있다.
- **실행 재현성**: README 순서만 따라 하면 어느 PC에서도 절대 경로 의존 없이 실행이 재현된다.

### 3.2 시뮬레이션 환경 구성 — 10점

Isaac Sim에서 다중 로봇 작업 환경을 목적에 맞게 구축하고 반복 실험이 가능한 구조로 만들었는지 평가한다.

- **씬 구성**: 환경·로봇·물체·센서 배치가 작업 목적에 적합하게 구성되어 있다.
- **물리 속성**: RigidBody·Collider·Mass·마찰력 등이 올바르게 설정되어 있다.
- **ROS2 연동**: clock, 이미지, tf 등 시뮬레이션 데이터가 ROS2로 정상적으로 연동된다.
- **재현성**: Play/Stop 반복 실행 시 매번 동일한 초기 상태에서 동일한 동작 결과가 재현된다.

### 3.3 개별 로봇 제어 — 25점

개별 로봇의 동작 시스템의 설계·구현을 평가한다.

- **개별 로봇 동작**: Pick & Place 또는 자율주행이 안정적으로 완수되고, 파라미터 튜닝 근거를 설명할 수 있다.
- **설계-구현 일치**: 문서화된 설계가 코드에서 동일하게 동작하고, 센서·토픽 등 외부 데이터가 동작 결정에 반영된다.

### 3.4 AI 비전 인식 및 활용 — 10점

AI 비전으로 환경을 인식하고, 그 결과를 로봇 동작(Pick 좌표, 회피, 감속, 분류 등)에 활용하는 파이프라인을 평가한다.

- **인식 안정성**: 감지 모델(YOLO, HSV 등)이 대상을 안정적으로 인식하고, 인식률 개선 과정을 설명할 수 있다.
- **인식 결과 활용**: 인식 결과가 로봇 동작에 실제로 반영된다.
- **처리 효율**: 추론 주기 제한 등 실시간 대응과 시스템 부하를 고려한 설계가 있다.

### 3.5 시스템 통합 및 동적 대응 검증 — 35점

다중 PC·다중 로봇이 하나의 시나리오로 통합되어 동작하고, 동적 상황에 대응하며, 결과를 정량적으로 검증했는지 평가한다.

- **시스템 통합**: 다중 PC 간 ROS2 통신이 정상이고, 시작부터 완료까지 전체 파이프라인이 끊김 없이 연결된다.
- **다중 로봇 조율**: 2대 이상 로봇의 작업 순서·역할이 충돌 없이 조율되고, 작업 완료 후 재실행이 가능하다.
- **동적 대응**: 물체 위치가 매번 달라져도(랜덤 스폰) 정상 동작하고, 외부 이벤트에 따라 동작이 결정된다.
- **검증 및 분석**: 성공률·소요 시간 등 사전 정의 기준으로 정량 측정하고, 실패 원인과 한계를 분석했다.

### 3.6 발표 및 시연 — 5점

PPT 및 발표가 제시한 문서 구성과 시간을 준수 여부를 평가

- flowchart, 시스템 아키텍쳐, 기술 스택 등

### 3.7 챌린지 — 5점

- 공학적 탐구, 알고리즘 개선 등 기술 리포트
- 센싱 데이터를 활용한 데이터 분석 및 머신러닝 적용 리포트
- 성능 개선을 위한 다양한 시도 기술 리포트

## 4. PPT 제작 원칙 — 작성 가이드

아래는 평가표를 발표 준비에 적용하는 제안이다. 강사가 추가로 배포한 채점 기준이 아니다.

1. **평가 항목 → 발표 주장 → 근거 → 영상 시점**을 연결한다. 기능 소개만으로 검증을 대신하지 않는다.
2. **통합 35점과 개별 제어 25점**에 충분한 설명과 시연 근거를 배정한다. 배점 비례로 발표 시간을 강제하지는 않는다.
3. 개별 기능을 설명한 뒤, 실제로 연결된 전체 공정의 시작·완료·재실행을 보여준다.
4. 설계도·코드·촬영 실행의 커밋과 설정을 맞춘다. 제안 중인 설계는 구현된 구조와 구분한다.
5. 성능 수치에는 조건·시행 수·실패 수·단위·측정 출처를 적는다. 성공 장면 하나로 안정성을 일반화하지 않는다.
6. 구현 완료, 단위/통합 검사 완료, Isaac 실행 확인, 미검증을 구분한다. 스텁 결과를 실제 시뮬레이션 검증으로 표기하지 않는다.
7. 비교 실험이 없다면 자체 알고리즘이 외부 솔버보다 빠르거나 안전하다고 주장하지 않는다. 선택 이유와 확인한 범위만 설명한다.
8. 발표 시간과 지정 구성이 확인되기 전에는 슬라이드 장수·초 단위 분량을 확정하지 않는다.

### 영상 준비 체크리스트

- [ ] 자막 또는 화면 표시로 현재 공정·로봇 역할·입력 이벤트·완료 결과를 알아볼 수 있다.
- [ ] 시작부터 완료까지 연결된 대표 실행과 작업 완료 후 재실행을 보여준다.
- [ ] 랜덤 스폰에 대한 대응과 외부 이벤트에 의한 행동 변화를 확인할 수 있다.
- [ ] 인식 화면과 해당 결과로 달라지는 로봇 동작을 연결한다.
- [ ] 배속·컷 편집·서로 다른 실행의 연결을 표시한다. 편집 시간을 사이클 시간으로 쓰지 않는다.
- [ ] 영상의 실행 커밋·설정·run ID 또는 추적 가능한 실행 기록을 보관한다.
- [ ] 성공 장면과 별도로 실패 유형·빈도·한계를 발표 근거에 포함한다.
- [ ] 발표 장소에서 영상·음성·글자 크기·재생과 전체 발표 시간을 확인한다.

### 재현성과 랜덤 스폰을 함께 보여주는 방법

동일 조건 재현 실험과 위치 변화 대응 실험을 구분한다.
전자는 초기 상태·seed·설정을 고정해 Play/Stop 뒤 결과를 비교한다.
후자는 사전에 정한 범위에서 위치·seed를 바꾸고 성공·실패를 모두 집계한다.
고정 위치 성공만으로 동적 대응을 입증하거나, 랜덤 조건 차이를 초기화 실패와 섞지 않는다.

[실험 protocol](../../../experiments/README.md), [evidence 절차](../../../evidence/README.md)를 따른다.
이 문서는 새로운 합격선·실험 횟수·성공률 목표를 정하지 않는다.

- 성공률은 성공 횟수와 전체 시도 횟수를 함께 표기하고, 실패·중단·timeout·재시도를 구분한다.
- 소요 시간은 시작/종료 이벤트와 사용한 시계, 단위, 집계 대상을 밝힌다.
- 사전 정의한 기준과 사후 분석을 구분한다. 결과를 본 뒤 만든 기준을 사전 기준으로 쓰지 않는다.
- 시뮬레이션의 제약과 물리 모델의 단순화를 밝히고, 시뮬레이션 결과를 실장비 검증으로 확대하지 않는다.

## 7. PPT 제작 착수·최종 검토 체크리스트

- [ ] 제작자·발표자·리뷰어가 본 문서의 출처, 110점 배점과 영상 발표 조건을 읽었다.
- [ ] 7개 평가 항목 모두에 설명할 내용과 증거 수집 담당을 연결했다.
- [ ] 발표 시간·지정 목차·영상 규격을 확인했거나, 미확인 상태를 계획에 표시했다.
- [ ] 전체 flowchart·시스템 아키텍처·기술 스택이 실제 발표 대상 구현과 일치한다.
- [ ] 로봇별 동작과 파라미터 선택 근거를 설명할 수 있다.
- [ ] 비전 결과가 실제 동작에 반영되는 과정과 처리 효율 근거가 있다.
- [ ] 다중 PC 통신·다중 로봇 조율·완료 후 재실행 증거가 있다.
- [ ] 랜덤 스폰·외부 이벤트 대응을 확인한 조건과 결과가 있다.
- [ ] 성공률·시간의 분모와 조건, 실패 원인·한계를 확인했다.
- [ ] README 기반 제3자 재현 범위와 미검증 환경을 명시했다.
- [ ] 챌린지의 개선 시도와 결과를 기술 리포트로 연결했다.
- [ ] 발표 자료의 수치·영상·코드 버전이 일치하고, 근거 없는 완료 표시가 없다.

향후 PPT 제작 요청에 함께 전달할 문구:

> `docs/reference/tutor/final-presentation-evaluation.md`를 먼저 읽고, 7개 평가 항목을 슬라이드와 영상 근거에 연결한다. 공식 평가 기준과 작성 제안을 구분하며, 미확인 시간·미측정 수치·미구현 기능을 임의로 채우지 않는다.

## 8. 추가 확인이 필요한 사항

| 항목 | 제공 이미지에서 확인한 범위 | 다음 확인 |
| --- | --- | --- |
| 발표 시간 | 시간 준수 요구만 있음 | 총 발표·영상·질의응답 시간 |
| 지정 문서 구성 | flowchart·시스템 아키텍처·기술 스택 등이 명시됨 | 별도 필수 목차·템플릿·슬라이드 수 |
| 영상 제출 | 최종 영상 발표와 직관적 편집 요구 | 해상도·길이·코덱·제출 방식·마감 |
| 배점 산정 | 항목 합계와 표기 총점 모두 110점 | 세부 배점·환산·챌린지 산정 방식 |
| 재현 환경 | 제3자 재현과 절대 경로 비의존 요구 | 평가 PC 환경·필수 설치 조건·비공개 저장소 접근 방법 |
| 개인 평가 | 이번 이미지에는 없음 | 별도 개인 평가 기준의 적용 여부 |

미확인 항목은 확인 전까지 빈칸 또는 미정으로 유지한다.
